# 웹 읽기 번역 범위 확대

2026-08-28 · 미공개 개발 변경 · 확장 0.7.11 · 본체 기능 정책 4

이 작업의 목표는 불필요한 차단을 줄이면서 기존 지원과 보호 경계를 유지하는 것이다.
로그인 사이트의 모든 화면이나 모든 웹메일을 완벽 지원한다고 판정한 문서는 아니다.
공개 릴리스·스토어 제출·원격 푸시는 하지 않는다.

## 변경 범위

| 영역 | 허용 범위 | 계속 제외하는 범위 |
| --- | --- | --- |
| 공개 문서 | 도움말·문서·뉴스 경로의 `settings`, `account`, `orders` 같은 단어 때문에 생기는 오차단 완화 | 미분류 개인 메시지 경로와 알려진 사적 서비스의 공개 수집 우회 |
| 공통 UI | 버튼·ARIA 버튼/탭/메뉴 항목·라벨·legend·입력란의 `aria-describedby` 설명·쿠키 안내 | 실제 입력값·선택값·편집기·숨긴 요소·명시적 번역 금지 |
| 계정·로그인·주문 | 구분 가능한 제목/항목명, 조작 문구, 연결된 설명, Product 이름·orderStatus | 임의 본문/값, 주소·Person·연락처·식별자·주문번호·금액으로 표시된 영역 |
| 가격 주변 | 별도 자식으로 구분된 세금 등의 설명 | 금액 노드와 숫자를 포함한 가격 조각 |
| Gmail 개발 경로 | 현재 열린 읽기 화면의 제목과 보이는 본문 | 목록·다른 메일·발신자/수신자 UI·초안·작성창·첨부 내용·숨긴 본문 |

계정 링크에는 사용자 이름이 표시될 수 있으므로, 계정 화면의 정적 UI를 허용해도
계정 목적지 링크를 일반 탐색 링크로 자동 승격하지 않는다. 기존 서비스별 닉네임·핸들
보호와 자연어 링크 번역, URL 표시·링크 목적지 보존을 유지한다.
HTML 의미와 서비스 경계에 근거한 제한이지, 임의 본문에 포함된 개인정보를 모두 탐지하거나
익명화하는 기능은 아니다. 표식 없는 이름이나 본문 속 민감 정보까지 제거한다고 안내하지 않는다.

## 확인한 원인과 공통 수정

- 경로의 모든 단어를 같은 민감 화면으로 간주해 공개 도움말도 차단했다. 일반 앵커와
  라우터 해시를 구분하고 공개 문서 경로와 정적 UI 전용 경로를 나눴다. 중첩된
  `/app/settings`, `/shop/account`와 언어 접두사는 제한을 우회하지 않는다.
- `form`, `button`, `label`, 쿠키·가격 컨테이너 제외가 안전한 안내까지 함께 막았다.
  `dom-policy.js`에 읽기용 UI 소유권을 추가하고 자식의 절대 보호 규칙은 다시 검사한다.
  하나의 Text 노드는 한 블록에만 속하며 기존 DOM·이벤트·입력 상태는 바꾸지 않는다.
- 입력 설명의 연결 속성이 나중에 생기면 입력 요소만 다시 검사해 형제 설명을 놓쳤다.
  `aria-describedby` 변경 때 해당 폼 또는 참조된 설명을 재검사한다. 입력값은 읽지 않는다.
- 정적 UI 전용 페이지에서는 전체 본문 진단과 임베드 제목 수집을 금지한다.
  SPA 경로 변경 직후, 정기 감시가 실행되기 전에도 현재 경로를 확인한다.
- 실제 본체에 합성 메일 문장을 전달하자 짧은 영어 제목은 언어 미확정으로 남고
  뒤의 본문만 번역됐다. 공통 `web_source_hints`가 같은 요청의 뒤쪽 문장을 근거로
  사용하도록 수정했다. 같은 문자군의 서로 다른 두 텍스트 조각 이상이 같은 언어로
  확정될 때만 보완하며, 본문 조각이 한 DOM 블록을 공유해도 처리한다. 언어 충돌·
  다른 문자군·다른 사적 읽기 문서에는 이 추론을 적용하지 않는다.
- 언어 미확정 원문을 완료된 번역으로 캐시할 수 있던 판정을 수정했다. 보호된 URL
  등의 의도적인 보존은 유지하고, 미확정 문구는 실제로 목표 언어로 바뀌었는지 확인한다.

## 메일 경계와 동의

`messenger-adapters.js`의 `readingDocumentContext`는 서비스가 제공한 읽기 창·제목·본문
경계를 공통 계약으로 처리한다. 제목 하나와 보이는 본문이 있어야 하며, 보이는 읽기 창이
둘 이상이면 선택하지 않는다. 경계 탐색은 텍스트·입력값을 읽지 않는다.

Gmail 연결은 실제 화면에서 본문이나 주소를 읽지 않고 확인한 DOM 메타데이터를 사용했다.
서비스 선택자는 사적 서비스에서 허용할 데이터의 경계이며, 문장 누락을 고치는 사이트 예외가
아니다. 도메인 없는 합성 읽기 문서와 별도의 합성 Gmail 셸로 계약을 검사한다.
Outlook 및 그 밖의 메일은 아직 연결·실사용 검증을 완료하지 않았다. 2026-08-28 사용자
요청으로 Outlook 실사용 테스트는 이번 검증에서 제외했다. 테스트 생략을 지원 구현 완료로
해석하지 않으며, 확인 없이 일반 본문 수집을 열지 않는다.

통합 안내 한 화면에서 웹 동의 **v2**, 사적 읽기 동의 **v4**를 함께 저장한다.
기존 웹 v1·메신저 v3는 자동 확대하지 않는다. 이전 기록도 같은 화면에서 철회할 수 있다.
Firefox의 `personalCommunications`와 본체의 `messengerPolicyVersion: 4`를 별도로 확인한다.
F4·상단 전체 토글만 유지하며 메일 전용 스위치는 추가하지 않는다.

Gmail도 기존 사적 요청 경로를 사용한다. 실제 메일 URL·ID·주소를 요청 식별자로 보내지 않고
`messenger:gmail:<임의 nonce>`를 쓴다. 일반 창은 앱의 번역기·암호화 캐시·보관/삭제 정책을,
시크릿 창은 디스크 비사용·지원 공급자 제한을 그대로 따른다. OFF/철회/페이지 전환의
늦은 응답 보호와 재표시 캐시도 공유한다. 통합 안내는 28개 언어에 새 범위를 명시했다.

### Gmail 실화면 확인 (2026-08-28)

사용자가 열어 둔 읽기 화면 한 건을 기존 Chrome의 설치된 확장과 실행 중인 본체로 확인했다.
저장소 문서·fixture·검증 로그 파일에는 해당 메일의 제목, 본문, 금액, 주소, URL,
스크린샷을 저장하지 않았다.
내용 비교는 메모리에서 수행하고 결과의 참/거짓 및 구조만 기록했으며, 비교 후 텍스트를
보관한 임시 변수도 비웠다. 입력값은 읽거나 변경하지 않았고 메일을 보내거나 삭제하지 않았다.

| 확인 항목 | 결과 |
| --- | --- |
| Gmail에 포커스를 둔 F4 | 제목·본문의 원문 복원과 번역 재표시 확인 |
| 번역 재표시 | 최초 번역 표시와 제목·본문이 일치 |
| 보호 경계 | 원문/번역 사이 발신자 표시 지문, 링크 목적지 지문, 숫자 토큰열 일치 |
| 작성창 | 편집 가능 영역의 수·태그·역할·자식 수 유지; 입력값은 검사하지 않음 |
| 스크롤 | 실제 읽기 영역 125px 이동 및 복귀 후 번역 유지 |
| 탭 전환 | 다른 탭에서 원래 읽기 화면으로 복귀 후 번역 유지 |
| 같은 메일의 새 탭 | F4나 확장 토글 조작 없이 제목·본문 자동 번역 확인 |

검증을 위해 만든 같은 메일의 복제 탭과 빈 탭만 닫고, 사용자가 열어 둔 탭과 기존의 번역 ON
상태는 유지했다. 확장 내부 팝업 URL은 브라우저 제어 도구의 보안 정책으로 열 수 없었으며
우회하지 않았다. 따라서 실제 확장의 전송 횟수나 캐시 적중 여부는 직접 관측하지 못했다.
동일한 번역 표시 복원만으로 재요청이 없었다고 단정하지 않는다. 재요청 수·철회·대화 전환은
기존 합성 E2E 검증 범위이며, 실제 메일에서 동의 철회나 다른 개인 메일 탐색은 하지 않았다.
이 표는 확인한 한 읽기 화면의 결과이며 Gmail의 모든 레이아웃·언어·메일을 완벽 지원한다는
의미가 아니다. Outlook 실사용 테스트는 사용자 요청으로 제외했다.

### 실제 본체 합성 입력 검증

`scripts/verify-live-reading-bridge.mjs`는 `--run`을 명시한 경우에만 실행한다.
최신 로컬 본체를 실행하고 모델 준비가 끝난 뒤 사용한다. 선택된 번역기가 로컬 모델인지,
웹 번역과 Chrome 연결이 이미 허용됐는지, 본체 정책이 v4인지 확인한다. 설정이나 브라우저
동의는 변경하지 않으며 검사 도중 번역기를 바꾸면 안 된다.

기존 합성 메일 fixture의 문구만 사용하고, 제목 하나와 같은 본문 블록의 텍스트 두 개로
요청한다. v3 동의·동의 누락·URL 형태의 식별자를 거절하는지 검사한 뒤 정상 요청을 두 번
실행해 각 항목의 대응, 한국어 결과, 완료 가능 여부를 확인한다. 요청은 `incognito: true`로
처리해 디스크 번역 기록을 남기지 않는다. 원래 앱 캐시의 적중률을 검증하는 명령은 아니다.
브라우저 프로필·로그인 메일·인증 토큰을 읽지 않고 실제 Native Messaging 호스트가 기존의
인증된 본체 연결을 사용한다.

첫 실행에서는 제목 `A neutral mail subject`가 원문이면서 `cacheable: true`로 반환돼
실패했다. 본문 조각을 서로 다른 블록으로 가정하지 않고 같은 블록으로 묶어서도 실패를
재현했다. 수정 후 제목은 `중립적인 메일 제목`, 두 본문 조각도 한국어로 반환됐고 두 회차
모두 완료 가능으로 판정됐다. 앱 창 표시 직후 아직 브리지가 준비되지 않은 시점의 연결
실패는 별도로 구분했으며, 준비 완료 후 같은 명령을 다시 실행해 통과를 확인했다.
