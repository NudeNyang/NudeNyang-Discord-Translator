# 웹 번역 동적 페이지 성능 회귀 수정

2026-08-31 · 확장 0.7.12

## 증상과 근본 원인

YouTube, 게시판형 목록처럼 ID가 많고 DOM이 계속 바뀌는 페이지에서 웹 번역을 켜면
콘텐츠 스크립트의 메인 스레드 작업이 반복됐다.

1. 읽기 전용 UI 설명을 판별할 때 모든 `[id]` 후보마다 문서 전체에서
   `aria-describedby` 입력을 다시 검색했다.
2. `MutationObserver`가 재생 상태·transform·애니메이션용 `class`와 `style`
   변경까지 번역 범위 변경으로 처리했다.
3. 이미 `IntersectionObserver`에 등록한 블록도 다시 수집될 때마다
   `getBoundingClientRect()`를 먼저 호출했다.
4. 번역 누락 진단이 일반 스캔·스크롤·결과 적용 뒤 자동 예약됐다.
5. 전체 ON 알림을 받은 숨겨진 탭도 즉시 전체 문서를 수집했다.

GPU 번역과 브라우저 렌더링의 자원 경합은 렉을 더 크게 보이게 할 수 있지만, 이번
수정은 모델 처리 모드를 낮추지 않고 콘텐츠 스크립트의 동기 DOM 작업을 제거한다.

## 수정

- 문서의 `input/select/textarea[aria-describedby]`를 처음 한 번만 인덱싱한다.
  입력의 값은 읽지 않는다. 입력 추가·삭제와 `aria-describedby` 변경은
  MutationObserver 기록으로 인덱스만 증분 갱신한다.
- 실제 블록·보호 선택자에 쓰이는 속성과 `hidden`, `inert`, `aria-hidden`,
  `contenteditable`, `role`, `translate`, 링크·작성자 의미 속성을 구분한다.
  의미 없는 class/style 변화는 전체 DOM 수집을 예약하지 않는다.
- CSS로 펼치는 본문과 메뉴는 현재 블록 또는 바뀐 상위 메뉴 범위만 다시 확인한다.
  표시 상태와 `display:contents` 전환은 유지한다.
- 이미 관찰한 블록은 레이아웃 측정 전에 반환한다. 실제 display 상태가 바뀔 때만
  boxless 목록을 다시 계산한다.
- 누락 진단은 테스트·개발 도구의 명시적 `nudenyang-audit` 요청에서만 실행한다.
- 전체 ON/OFF의 브라우저 공통 의미는 유지한다. 숨겨진 탭은 상태만 갱신하고
  보이게 될 때 캐시 표시와 수집을 재개한다.

## 수정 전후 계측

같은 jsdom 합성 DOM을 작업 전 HEAD와 수정 코드에 각각 실행했다. 시간은 jsdom
참고값이고, 문서 전체 `querySelectorAll` 호출 수가 실제 회귀 기준이다.

| 구조 | 문서 전체 조회 전 → 후 | 설명 참조 조회 전 → 후 | 참고 시간 전 → 후 |
| --- | ---: | ---: | ---: |
| YouTube형 카드 500개 | 4,502 → 3 | 4,500 → 1 | 609.1ms → 550.4ms |
| 범용 article 500개 | 56,504 → 5 | 56,500 → 1 | 8,231.8ms → 8,141.1ms |
| 범용 article 1,000개 | 113,004 → 5 | 113,000 → 1 | 16,576.6ms → 16,099.9ms |

범용 fixture는 ID 네 개와 본문 블록 두 개를 한 행에 둬 정책 검사를 의도적으로 많이
호출한다. 크기를 두 배로 늘려도 수정 후 문서 전체 조회는 5회로 고정됐다. 같은 관찰
블록에 class/style 변경을 다섯 회 가한 런타임 재현에서는 추가 강제 레이아웃 호출이
수정 전 10회, 수정 후 0회였다. 수정 후 DOM 재수집용 요소 조회와 새 번역 요청도 0회다.

## 회귀 검증 범위

- YouTube fixture와 범용 article/게시판형 대규모 ID 구조
- 빠른 class/style 변경과 늦은 문단 삽입
- CSS 메뉴 표시, boxless 문단, 가상 목록 재생성
- hidden, inert, aria-hidden, contenteditable, form, 작성자·닉네임·URL 보호
- Gmail/Outlook 합성 읽기 범위와 동의한 메신저 경계
- OFF 원문 복원과 현재 페이지 번역 재사용
- 명시적 누락 진단과 숨겨진 탭 재개

실제 로그인 서비스와 Whale 프로필의 성능 수치는 자동 E2E가 대신하지 않는다. 개인용
확장을 다시 로드한 뒤 Whale 작업 관리자에서 해당 탭의 CPU와 응답성을 별도로 확인한다.

## 2026-09-01 동적 목록 요청 묶기

가상 스크롤 목록은 한 화면에 들어올 여러 게시물을 한 번의 DOM 작업이 아니라 짧은 간격의
여러 MutationObserver 작업으로 추가할 수 있다. 기존 구현은 새로 보이는 블록을 우선순위
작업으로 올리면서 매번 대기 시간 0ms로 전송을 시작했다. 이 때문에 8ms 간격으로 문단 8개를
추가하는 사이트 독립 fixture에서 네이티브 번역 요청도 8회로 갈라졌다. 수집 누락은 아니지만
로컬 모델 요청이 직렬로 쌓여 빠르게 스크롤한 직후에는 번역이 빠진 것처럼 오래 보였다.

우선순위 작업의 순서는 유지하되 최초 항목부터 최대 80ms 동안 같은 동적 삽입 묶음을
수집한다. 일반 처리 모드의 기존 수집 지연보다 길어지지 않으며, 이미 진행 중인 요청이 끝난
뒤 대기 중인 작업은 즉시 이어서 처리한다. 같은 fixture에서 수정 전 8회였던 네이티브 요청은
수정 후 1회이고 문단 8개가 모두 번역되는지 E2E로 함께 검사한다. 이 수치는 합성 DOM의 요청
분할 회귀 기준이며 실제 로그인 서비스의 네트워크·모델 지연 측정값은 아니다.
