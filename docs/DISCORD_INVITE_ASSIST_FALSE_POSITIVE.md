# 이모지 선택기에 표시된 초대 안내 조사

## 관찰과 원인

2026-09-20에 제보된 23.83초 영상을 확인했다. 이모지 선택기가 열린 화면 아래에
NudeNyang의 `초대 수락이 완료되지 않으면 브라우저에서 계속해 주세요.` 안내가 나타난다.
이는 Discord 자체 초대 수락 창이 아니라 `invite_assist.rs`가 추가하는 안내이다.
제보 환경은 Discord stable 615002 (1267885), Host 1.0.9258 x64, Windows 11 26200이다.
첨부 영상과 개인 대화 내용은 저장소에 포함하지 않는다.

기존 구현은 2026-08-14의 `a8a1215`에서 추가되었으며, 다음 조건이 겹치면 오탐한다.

- 초대 URL을 포함한 메시지 안에서는 반응 추가나 일반 본문 클릭도 초대 선택으로 기록한다.
- 기록한 초대 코드는 창을 닫거나 채널을 바꾸어도 만료되지 않는다.
- 이후 보이는 `role=dialog`의 전체 `innerText`에 `invite`, `invitation` 등의 문자열이
  있으면 초대 창으로 판단한다. 이모지 이름과 서버 이름도 검사 대상에 섞인다.
- 숨겨진 초대 구조가 다른 창 내부에 남아 있어도 구조 존재만으로 초대로 판단한다.

영상에서 안내 문구와 선택기 열림에 따른 동작은 확인했지만, 원래 DOM과 이전 클릭 기록은
없다. 따라서 실제 환경에서 걸린 정확한 문자열은 미확정이다. 별도 HTML fixture에서 위
조건으로 같은 오탐을 재현했으며, 최근 CPU/캐시 변경이 이 판정을 추가한 것은 아니다.
CAPTCHA 때 연결을 분리하는 기능에 대한 언급은 별도 보호 동작이며 이번 수정에서 유지한다.

## 수정

- 초대 링크 자체 또는 초대 메시지의 명시적인 수락·가입 버튼을 누른 경우에만 추적한다.
- 기존 초대 전용 구조는 실제 표시 여부를 검사한다. 그 외 창은 제목/접근성 이름에 초대
  의미가 있고, 보이는 수락·가입 버튼도 있을 때만 인정한다. 일반 본문·이모지 항목은
  창의 용도를 판단하는 근거로 사용하지 않는다. 새 사이트별 선택기 예외는 추가하지 않는다.
- 선택 후 2분 동안 초대 창이 열리지 않거나 채널이 바뀌면 추적을 해제한다. 확인한 초대
  창은 계속 열려 있는 동안 유지하며, 닫히거나 다른 내용으로 바뀌면 해제한다.
- 재연결 시 남아 있을 수 있는 구버전의 영구 속성은 새 판단에 사용하지 않는다.
- 초대 전용 경로, 잘못된 초대 카드의 안내와 사용자가 누르는 브라우저 이동은 보존한다.
  초대 자동 수락, 인증 자동 처리, Discord API 호출은 추가하지 않는다.

## 재현과 검증

`extension/e2e/invite-assist.spec.mjs`는 Rust에 포함된 실제 주입 스크립트 전체를 실행하며
언어 카탈로그 인자만 한국어로 공급한다. Discord를 흉내 낸 최소 HTML과 격리 Chromium을
사용하고, 실제 사용자 계정이나 친구의 대화는 사용하지 않는다.

수정 전 `npm run test:e2e -- invite-assist.spec.mjs`에서 8개 중 5개가 실패했다.
모두 없어야 하는 안내가 1개 나타나는 실패였다: 이모지 이름, 반응 추가 클릭, 닫은 창의
기록 재사용, 미사용 기록의 만료, 숨겨진 초대 구조. 정상 초대 관련 3개는 통과했다.

수정 후에는 구버전 속성/재주입 검사와 `discord-focus.spec.mjs`의 실제 Rust 엔진/CDP
주기 검사도 추가했다. 대상 검사 10개가 통과했다. 실제 엔진 검사는 초대 창으로 확인된
DOM이 이모지 창으로 바뀌었을 때 안내가 사라지고 인증 필요 상태가 되지 않는지 확인한다.

전체 검증 결과:

- `npm test`: 785개 통과, 사전 팩 검증 통과.
- `npm run test:e2e`: 199개 통과. 기존 인증 감지·연결 분리 검사를 포함한다.
- `cargo test --manifest-path src-tauri/Cargo.toml -- --test-threads=1`:
  493개 통과, 환경/실서비스 전용 50개 제외. 실제 사용자 데이터와 분리한 임시
  `LOCALAPPDATA` 및 `DISCORD_TRANSLATE_CONFIG` 경로에서 실행했다.
- `cargo fmt --manifest-path src-tauri/Cargo.toml -- --check`, `npm run test:locales`,
  `git diff --check`: 통과.

공통 웹 DOM 수집·가시성·적용 경로는 변경하지 않으므로 공개 웹 표본 검사는 이번 변경의
검증 대상이 아니다. 실제 로그인 Discord의 해당 버전에서 같은 클릭 경로를 재현한 검증
및 ARM64 실기기 실행은 별도이다.
