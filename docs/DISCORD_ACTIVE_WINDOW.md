# Discord 활성 창 번역

## 사용자 동작

- 기존 Discord 선택 항목의 기본 자동 모드는 `자동 · 사용 중인 창`이다. 별도 탭이나 배포판별 스위치를 추가하지 않는다.
- Stable·PTB·Canary를 함께 실행하고 클릭 또는 Alt+Tab으로 사용할 창을 선택한다. 마지막 실행 시각으로 대상을 정하지 않는다.
- 받은 메시지 번역, 보내는 메시지 통역, 모델과 언어 설정은 전역으로 공유한다.
- 다른 프로그램을 사용하는 동안 새 메시지 수집과 번역 결과 적용을 멈춘다. 이미 적용된 번역은 유지한다.
- 실시간 번역을 끄면 연결된 세 배포판의 원문을 모두 복구한다. 다시 켜면 활성 Discord부터 번역한다.
- 보내는 메시지의 결과는 요청한 작성창으로 돌아온 뒤에만 적용한다. 다른 배포판의 초안을 덮어쓰지 않는다.
- 상태 표시줄과 트레이에는 마지막으로 선택한 배포판을 표시한다. 특정 배포판 고정 선택도 유지한다.
- 자동 모드는 실행하지 않은 Discord를 임의로 시작하지 않는다. 최초 보안 연결에는 기존 안내·동의·재시작 절차를 사용한다.

## 구현 경계

`discord_focus.rs`는 Windows 전경 HWND의 PID를 확인한다. `discord.rs`는 실행 파일 경로가
확인된 Discord 프로세스와 대응시킨다. 컨트롤러는 배포판별 연결, DOM 원문, 작업 세대,
화면 세대, 이미지·작성창 요청과 인증 중지 상태를 보존한다. 로컬 모델과 번역 워커는 공유한다.

작업 세대 상위 비트로 배포판을 구분하고, 대기 작업 제거도 배포판별로 수행한다. 이전의
단일 최대 세대 비교는 다른 배포판의 유효 작업을 버렸으므로 제거했다. 전경 PID를 다시
확인하고 CDP의 `document.hasFocus()`까지 확인한 후에만 수집·결과 적용을 허용한다.
동일 프로세스의 보조 창이 활성화되어 기본 채팅 문서에 포커스가 없으면 수집하지 않는다.

비활성 연결에는 메시지 수집 없이 컨트롤 상태와 생존 신호만 전달한다. 전역 OFF·앱 종료는
모든 연결을 정리한다. 재시작에는 요청 당시 PID를 전달하며, 인증용 재시작도 현재 활성
세션 대신 요청한 배포판의 세션을 중지한다. 추가 인증 중지는 배포판별로 저장한다.

## 검증 방법

`npm run test:e2e`는 전체 브라우저 E2E를 실행한다. `discord-focus.spec.mjs`는 실제
Rust 컨트롤러·CDP·주입 스크립트·워커를 사용하고, OS 프로세스/포커스 관찰과 번역 모델만
대체한다. Chromium은 격리 프로필과 로컬 테스트 문서를 사용한다.

- 세 배포판 전환, 비활성 창의 기존 번역 유지, 비활성 새 메시지 제외
- 렌더러 생존 검사 시간을 넘긴 대기 후 유지 및 전역 OFF 원문 복구
- 한 배포판의 추가 인증·연결 종료가 다른 배포판에 영향을 주지 않음
- 배포판 고정 선택과 자동 모드 복귀
- 지연된 보내기 번역의 원래 작성창 적용 및 다른 초안 보존
- 인증 재시작 요청 후 포커스가 바뀌어도 원래 배포판만 중지

마지막 항목은 수정 전 실제 실패를 확인했다. Canary 인증 중지를 요청했지만 활성 Stable이
중지되고 Canary 번역이 남았다. 요청 배포판·PID로 세션을 선택하도록 수정했다.
작업 세대 회귀 테스트도 수정 전 유효 작업 3개 중 1개만 남는 실패를 확인했다.

실제 로그인된 Discord와 로컬 모델 검증은 위 모사 테스트와 별도로 수행한다. 전송 메시지는
실제 서버에 보내지 않으며, 지연 결과·작성창 경계 검증은 격리 E2E로 확인한다. ARM64 설치본
생성과 실제 ARM64 하드웨어 실행 검증도 구분한다.

## 2026-09-06 검증 결과

- `cargo test --manifest-path src-tauri/Cargo.toml`: 478 통과, 50개 명시적 환경/실행 테스트 제외.
- `npm test`, `cargo fmt --manifest-path src-tauri/Cargo.toml -- --check`, `npm run test:locales`: 통과. 인터페이스 28개 언어를 검증했다.
- `npm run test:e2e`: 최종 177개 통과. 위 Discord 컨트롤러 E2E 5개를 포함한다.
- `npm run test:public`: 5개 통과, 기사 표본 1개는 번역 시작 전 외부 주소 HTTP 404로 실패했다. 번역 성공으로 계산하지 않는다.
- Windows x64 실제 설치된 Stable 1.0.9256, PTB 1.0.1219, Canary 1.0.1158을 함께 실행했다. 기존 Stable 연결을 유지하면서 PTB·Canary를 각각 보안 파이프로 재연결했고, 각 대상 이름이 앱 상태에 표시되는 것을 확인했다.
- Stable 공개 이벤트 메시지, PTB 공개 규칙 본문, Canary 공개 이벤트 임베드가 실제 Hy-MT2 1.8B 설정에서 한국어로 표시되는 것을 확인했다. 로컬 모델의 캐시 미사용 추론 기록도 확인했다.
- Canary에서 F12를 눌러 번역을 끄자 Canary 영어 본문과 PTB 다국어 규칙 원문이 함께 복구되었다. PTB에서 다시 켠 후 해당 창의 한국어 번역 재개도 확인했다.
- 최종 전역 OFF의 Stable 공개 표본 복구는 실제 화면에서 추가 확인하지 않았다. 세 배포판 동시 복구와 비활성 창의 새 본문 제외는 격리 E2E로 검증했다. 실제 메시지 전송, 실제 CAPTCHA/추가 인증 완료, ARM64 하드웨어 실행은 수행하지 않았다.
- `scripts/package_windows_variants.ps1`: x64·ARM64 설치본 모두 생성했다. 최초 실행은 테스트 실행본의 파일 잠금으로 실패했으나 해당 실행본 종료 후 전체 패키징이 통과했다. 재시도의 x64 번들 표시 경고는 바이너리에 NSIS 표시(`NSS`)가 이미 존재함을 직접 확인했다.
- 프로젝트 바로가기는 `dist/NudeNyangDiscordTranslator/NudeNyangDiscordTranslator.exe`를 대상으로 작업 폴더·아이콘을 동기화했다. 바로가기로 실행한 프로세스 경로와 제품 버전 `0.7.5-beta`, x64 빌드 파일과 배포 실행본의 SHA-256 일치를 확인했다. 원격 푸시·릴리스 게시·공개 업데이트 변경은 하지 않았다.
