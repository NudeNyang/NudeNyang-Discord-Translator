# Discord 스크롤 응답성 — 0.7.6-beta 개발자판

## 원인

Discord가 스크롤 중 메시지 DOM을 재생성하면 `dto-message-*` 임시 locator가 바뀐다.
기존 `states` 빠른 복원은 이 locator에 의존했으며, 실패하면 번역 워커 차례가 돌아와야
메모리·SQLite 캐시를 조회했다. 같은 채널의 스크롤은 경로 세대를 바꾸지 않으므로
화면 밖 미시작 작업도 남았다. 워커가 묶음 전체를 마쳐야 결과를 보내는 구조도 지연을 더했다.

보호 토큰 마스킹은 메시지 우선순위를 바꾸지 못하게 하는 제약이 아니다. 다만 로컬 모델은
보호 토큰 사이 자연어 조각을 순차 번역한다. 이 버전은 그 품질·복원 계약을 유지하고,
완성된 메시지를 재사용할 때에는 마스킹과 모델 호출 모두를 건너뛴다.

## 구현

- 실제 메시지·행 ID를 문맥 식별에 사용한다. DOM 적용 locator는 계속 요소별로 유지하여
  재생성된 노드나 다른 메시지에 이전 번역이 붙지 않게 한다.
- 완성된 메시지의 복원은 추론 워커와 독립적인 공유 캐시에서 수행한다. 현재 번역기의
  캐시 namespace(모델·프롬프트 포함), 채널 경로, 메시지 문맥, 원문 조각·순서,
  대상 언어와 원문 언어 필터를 해시 키에 포함한다. 익명 원문·채널 ID를 로그에 남기지 않는다.
- 메모리는 최대 1,024개 메시지·본문/키 8MiB로 제한하고 해시 조회를 사용한다.
  캐시 미존재도 최대 1,024개 기억하여 같은 미번역 화면을 확인할 때 SQLite를 반복 조회하지 않는다.
  완성 결과가 저장되면 해당 미존재 기록을 제거한다.
- SQLite의 별도 `display_replay` 표에는 복원된 결과 배열만 기존 DPAPI 암호화로 저장한다.
  번역 기록 목록에는 중복으로 표시하지 않고 기존 전체 삭제·기간 만료 삭제에 포함한다.
  삭제 전 무효화 세대를 바꿔 실행 중이던 작업이 삭제된 복원 캐시를 다시 쓰지 못하게 한다.
- 매 수집 때 배포판별 최신 가시 작업 목록을 교체한다. 워커는 아직 시작하지 않은
  메시지가 화면에서 사라지거나 변경됐으면 건너뛴다. 이미 시작한 메시지는 끝내고
  결과를 캐시에 남길 수 있으며 다음 메시지 전에 가시 목록을 다시 확인한다.
- 메시지별 완성 결과를 즉시 전달한다. 같은 메시지의 비연속 조각도 모아 처리하고,
  원래 묶음에서 얻은 언어 근거를 이어서 사용한다. 웹·사전과의 순번 교대는 유지한다.
- 편집 후 원문 보관 정보를 갱신한다. 늦게 도착한 결과는 수집 당시 표시문과 현재 표시문이
  다르면 적용하지 않는다. 전송 원문 표시·편집기·수정 시각의 기존 보호는 유지한다.

## 한계

이전 버전의 일반 번역 캐시는 삭제하지 않는다. 그 캐시만 있고 완성 메시지 복원 기록이
아직 없다면 최초 한 번은 기존 워커에서 캐시를 읽어 복원 기록을 만든다. 이후에는 새 경로로
재사용한다. 원문 그대로 반환된 미확정·실패 결과는 완성 번역으로 저장하지 않는다.

진행 중인 긴 메시지의 추론을 강제 중단하지 않는다. 보호 토큰의 분할 추론을 단일 호출로
바꾸거나 프롬프트를 변경하지 않으며, CPU 스레드 수를 늘리지 않는다. 실제 친구 PC의
CPU 100% 원인·메모리 사용량·게임 FPS 개선까지 입증한 변경은 아니다.

## 재현 및 검증

수정 전 아래 세 격리 E2E가 각각 실패했다.

- `scroll replay restores a remounted message while another inference is busy`:
  다른 번역이 실행 중일 때 같은 원문·메시지를 새 DOM으로 만들면 900ms 내 복원이 되지 않았다.
- `scroll work publishes the first complete message before the rest of its batch`:
  1.2초 지연 모델에서 첫 메시지가 2.2초 내 표시되지 않았다.
- `scroll work discards unstarted messages after they leave the same channel viewport`:
  첫 추론 시작 후 메시지 목록을 바꾸면 새 메시지가 3.3초 내 표시되지 않았다.

E2E는 실제 Rust 컨트롤러·CDP·DOM·캐시·워커와 격리 Chromium을 사용한다. OS 포커스/프로세스와
번역 모델은 대체한다. 모델 시작/완료 횟수로 실행 중 상태를 확인하며 합성 문장만 사용한다.
복원 표본에는 멘션·URL·이모지를 포함한다. 실제 로그인 Discord나 실모델 CPU 벤치마크는 아니다.
Rust 검사는 캐시 경계, 메모리 상한, 비연속 문맥, 배포판 격리, 암호화된 파일 재개방과
기간 만료·전체 삭제·삭제 중 추론의 복원 기록 무효화를 확인한다.

최종 소스 검증 결과:

- `npm test`: 785개 통과(웹 269, 랜딩 38, 확장 469, 스크립트 9).
  독립 수집 진단과 2,048개 자동 생성 구조 검사를 포함한다.
- `npm run test:e2e`: 전체 186개 통과(4.5분). 새 스크롤 재현 3개와 기존 편집·원문 전환,
  다중 Discord 배포판, 메시지 보호, 32개 구조 조합 브라우저 검사를 포함한다.
- `cargo test --manifest-path src-tauri/Cargo.toml -- --test-threads=1`:
  493개 통과, 기존 환경 의존 검사 50개 제외(135.14초).
- `npm run test:locales`, `cargo fmt --manifest-path src-tauri/Cargo.toml -- --check`,
  `git diff --check`: 통과.
- `npm run test:public`: 5개 통과, `news-article` 표본 1개는 번역 시작 전 HTTP 404로 실패.
  공개 표본 전체 성공으로 처리하지 않는다. 표본이나 제품 selector를 우회 변경하지 않았다.

검증 중 반복 편집 뒤 원문 복원 회귀를 발견하여 최신 원문 보관을 보완했고 기존 E2E가 통과했다.
새 이모지 표본의 초기 실패는 테스트 HTML의 문자 인코딩 미선언 때문이었다. UTF-8을 명시한
표본으로 전체 E2E를 다시 실행한 결과가 위 수치다. 모델 추론의 보호 토큰 규칙은 변경하지 않았다.

## 배포 범위

앱·npm·Cargo·Tauri의 개발 버전은 `0.7.6-beta`다. 공개 랜딩 다운로드, 확장 버전,
`updates/beta/latest.json`, 공개 릴리스는 변경하지 않는다. x64·ARM64 설치형은 로컬에서만
생성하고, 개발자 실행 파일과 Tauri 바로가기를 최신 x64 실행본에 맞춘다.

최종 로컬 패키징·실행 확인:

- `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/package_windows_variants.ps1`:
  x64·ARM64 최적화 빌드와 NSIS 설치형 생성 성공. 설치 파일 크기는 각각
  150,976,454바이트와 142,725,056바이트다. ARM64 실기기에서는 실행하지 않았다.
- 개발자 실행 파일은 `dist/NudeNyangDiscordTranslator/NudeNyangDiscordTranslator.exe`다.
  x64 빌드와 개발자 파일의 SHA-256 일치를 확인했다.
- `NudeNyang Discord Translator (Tauri).lnk`의 대상·작업 폴더·아이콘을 동기화했다.
  정확한 기존 앱 실행 경로로 식별한 본체·브라우저 브리지 프로세스만 종료한 뒤 바로가기로
  실행했다. Discord 자체와 별도 파이프 guardian은 종료하지 않았다.
- 새 본체의 실행 경로와 제품 버전 `0.7.6-beta`를 확인했다. 실제 로그인 대화의 번역 지연이나
  실제 CPU 성능 비교를 수행한 검증은 아니다.
- 원격 푸시, 공개 릴리스, 공개 업데이트 목록 및 확장/랜딩 다운로드 변경은 하지 않았다.
