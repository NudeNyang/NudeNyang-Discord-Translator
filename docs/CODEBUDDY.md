# CodeBuddy 번역 제공자

이 문서는 NudeNyang Discord Translator가 CodeBuddy CLI를 번역 제공자로 사용하는
방식을 설명한다. CodeBuddy는 표시 번역과 보내는 메시지 통역에서 모두 선택할 수 있다.

## 구분

- 네이티브 CodeBuddy CLI 실행 파일을 직접 실행한다. `cmd` 래퍼가 아닌
  `codebuddy.exe`를 우선 사용한다.
- 앱은 CodeBuddy CLI를 설치하지 않는다. 사용자가 이미 설치하고 로그인한 CLI의
  기존 로그인을 그대로 사용한다.
- 앱은 API 키를 요구하지 않고, CodeBuddy의 인증 정보를 읽거나 복사하지 않는다.
- 번역할 때 선택한 텍스트만 외부로 전송된다. 외부 전송 제공자이며 세션은 유지하지 않는다.

## 설치와 연결

1. 사용자가 CodeBuddy CLI를 설치하고 로그인한다.
2. 설정의 연결 목록에서 CodeBuddy 카드가 설치 여부를 표시한다.
3. 카드의 연결을 선택하면 기존 로그인을 확인한다.
4. 연결 해제는 이 앱에서의 사용만 중지하며, 사용자가 만든 CLI 로그인은 그대로 유지한다.

설치 여부 확인은 실행 파일의 존재만 검사한다. `--version` 출력이나 실행 파일 존재로
계정 로그인까지 확인했다고 표시하지 않는다. 연결을 선택하면 현재 선택한 모델로 아주 작은
고정 번역을 한 번 수행하여 기존 로그인과 모델을 검증한다. 이 검증은 사용자가 명시적으로
연결을 선택할 때만 실행되며, 설정 목록을 새로 고칠 때마다 요청을 만들지 않는다.

검증 표시는 마지막으로 확인한 모델 ID에 연결된다. 다른 모델을 선택하면 이전 모델의 검증을 재사용하지 않는다. 이 표시는 이전 검증 기록이며 실시간 계정 상태 확인은 아니다.

CodeBuddy CLI를 찾지 못하면 자동 설치를 시도하지 않고 설치 안내를 표시한다.
자동 설치와 브라우저 로그인 절차는 ChatGPT, Claude, Gemini에만 적용된다.

## 모델 설정

- 설정 키는 `codebuddy_model`이며 기본값은 `hy3`이다.
- 선택 가능한 모델 목록은 CodeBuddy CLI의 `--help` 출력에서 확인한 실제 네이티브 모델과
  사용자 지정 모델을 기준으로 표시한다. 이 목록은 설치된 CLI 버전에 따라 달라질 수 있다.
- 모델 목록 새로 고침은 추론 요청을 만들지 않고 CLI의 모델 목록만 다시 읽는다.
- 목록에 표시된 모델 이름은 사용 가능한 후보일 뿐이며, 모든 모델이 실제 번역 요청으로
  검증되었다는 뜻은 아니다.
- 모델은 `--model` 인자로 전체 ID 그대로 전달된다. 목록에 없는 모델 ID라도 현재 저장한
  선택을 그대로 유지하며, 콜론, 슬래시, 마침표, 하이픈이 포함된 ID를 축약하거나 별칭으로
  바꾸지 않는다.
- 저장 값은 비어 있지 않은 문자열이며 최대 120자, 영숫자와 `: / . - _`만 허용한다. 생략한 값은 `hy3`이며 명시한 잘못된 값은 오류로 처리한다. 다른 모델로 자동 대체하지 않는다.
- 캐시 네임스페이스에 모델 ID가 포함되므로 모델을 바꾸면 이전 모델의 번역 결과를
  재사용하지 않는다.
- 표시 번역이나 보내는 메시지 통역에서 CodeBuddy를 쓰는 중이면 모델을 바꿀 때 해당
  작업 영역만 다시 준비한다.

## 사용량과 과금

- 원생 CodeBuddy 모델은 CodeBuddy 계정의 인증과 사용량을 사용한다. viito 경로는 CLI에 구성한 해당 경로의 인증과 사용량을 사용한다. 두 경로의 할당량이나 요금은 같다고 가정하지 않는다.
- 앱은 무료 제공이나 고정 요금을 보장하지 않는다.
- 설정 목록 새로 고침, 설치 여부 확인, 상태 표시는 별도 요청을 만들지 않는다.
- 과금이 발생할 수 있는 요청은 실제 번역과 사용자가 선택한 연결 검증뿐이다.

## 실행 방식

번역 요청 하나마다 CodeBuddy CLI 프로세스를 하나만 실행한다. 지속 세션을 만들지 않으므로
요청 사이에 대화 문맥이 누적되지 않는다.

- 프롬프트는 표준 입력(STDIN)으로 전달한다. 메시지 본문이 명령줄에 나타나지 않는다.
- 출력은 `--output-format stream-json`의 JSON 줄 스트림으로 받는다.
- 최종 결과가 나오고 프로세스가 끝날 때까지 기다리되 120초로 제한한다.
- 표준 출력과 표준 오류는 상한이 있는 동시 수집 도우미로 읽는다.
- 실패하면 표준 오류의 짧은 발췌와 종료 상태를 함께 보고한다.

표시 번역에서는 CodeBuddy가 완전한 메시지 문맥을 한 번에 최대 8개까지 묶어 보낸다.
다른 제공자는 기본값 1개를 사용한다. 묶음은 합계 4000자로 제한하며, 메시지 문맥을
중간에서 나누지 않는다. 첫 문맥은 크기와 관계없이 항상 통째로 포함한다.

묶음 실패와 재시도 예산은 메시지 문맥 단위로 추적한다. 실패한 문맥은 보류 목록으로 분리해 두고, 이후 새 메시지 묶음은 정상적으로 진행한다. 보류된 문맥은 이전에 실패한 시도 횟수를 유지하며, 재시도 예산을 소진하면 원문을 유지한다. 자동 모델 검증이 실패하면 전역 설정 상태는 그대로 유지하고 해당 실패만 기록하며, 설정 목록의 수동 새로 고침은 계속해서 오류를 표시한다.

전달하는 인자 순서는 다음과 같다.

```
-p --model <모델 ID> --output-format stream-json --verbose
--tools "" --disallowedTools * --permission-mode dontAsk
--strict-mcp-config --mcp-config {"mcpServers":{}} --no-session-persistence
--max-turns 1 --system-prompt <번역 전용 시스템 프롬프트>
```

`--tools ""`는 빈 문자열 인자를 함께 전달하고, `--disallowedTools *`로 모든 도구를
막는다. 다만 CodeBuddy CLI의 초기화 출력에 도구 이름 목록이 표시될 수 있으므로, 그
목록을 근거로 허용된 도구를 보장했다고 표현하지 않는다.

`--json-schema`는 처음에는 사용하지 않는다. 구조화 출력 도구를 요구할 수 있으므로
필요한 JSON 구조를 프롬프트 안에 설명한다.

시스템 프롬프트는 모든 텍스트 필드를 지시가 아닌 신뢰할 수 없는 내용으로 취급하고,
문장 끝 문장부호를 임의로 추가하지 않으며, 요청한 스키마에 맞는 JSON 객체 하나만
응답하도록 지시한다.

## 결과 처리

- 스트림에서 마지막 `type: "result"` 줄을 최종 결과로 사용한다.
- 프로세스 종료 코드가 0이고 최종 `subtype`이 `success`이며 `is_error`가 거짓이어야 성공이다. 그 외에는 실패로 처리한다.
- 결과가 없으면 불완전 응답으로 실패 처리한다.
- 최종 페이로드는 `structured_output` 또는 `result`의 JSON 문자열에서 읽는다.
- 요청한 모든 id가 정확히 한 번씩 있어야 한다. 중복 id, 범위를 벗어난 id,
  누락된 id, 텍스트 필드가 없는 항목은 거부한다.
- 자동 대체 모델이나 자동 대체 제공자를 사용하지 않는다. 인증 실패 등 실제 실패는
  그대로 사용자에게 보고한다.

## 한계

- CodeBuddy CLI가 설치되어 있지 않으면 동작하지 않는다. 앱 안에서 설치할 수 없다.
- CLI 로그인이 없으면 첫 연결에서 실제 인증 오류가 표시된다.
- 모델 ID와 사용 가능한 모델은 CodeBuddy 쪽 사정으로 바뀔 수 있다.
- 요청마다 프로세스를 새로 실행하므로 지속 세션 방식보다 시작 비용이 크다.
- 회귀 테스트는 모사한 CLI 스트림을 사용한다. 별도의 무시된 테스트는 로그인된 Hy3로 고정된 영어·중국어 문장을 실제 번역한다. 이는 사용자의 Discord 전송 동작 전체에 대한 수락 검증과 구분한다.

## CodeBuddy 동작 요약

- CodeBuddy는 자동 품질 재시도를 하지 않는다.
- 실패한 수신 조각과 형식이 잘못된 컨텍스트는 원문을 유지한다.
- 엄격한 경로는 오류로 처리한다.
- 알 수 없는 발신 언어는 제공자에게 전달한다. 기본 품질 검사에서는 다른 스크립트의 변경되지 않은 결과를 렌더링 전에 거부하며, 전역 누락 검사 해제 설정을 존중한다.
- 첫 번째 Enter는 검토용이고, 두 번째 물리적 Enter에서 전송한다.
- 모델과 CLI 시작 지연은 그대로 남는다.

## 수신 묶음의 부분 품질 실패

수신 표시 번역에서 한 묶음 안의 일부 조각이 최종 품질 검사를 통과하지 못해도, 실패한
조각만 원문으로 남기고 같은 묶음의 정상 번역은 함께 표시한다. 수신 번역은 기존처럼 하나의
제공자 묶음으로 처리하며, 실패한 조각의 결과는 캐시에 저장하지 않는다. 이 완화는 수신
표시 번역에만 적용하고, 보내는 메시지 통역과 사전·웹의 엄격 경로는 그대로 유지한다.
전송·인증·전송 계층 실패는 계속 실제 오류로 보고하며 성공으로 처리하지 않는다.
