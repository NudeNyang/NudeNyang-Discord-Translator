# 브라우저 확장

`extension/`은 NudeNyang Windows 앱을 번역 엔진으로 사용하는 Manifest V3 확장이다. Chrome, Naver Whale과 Firefox가 번역·팝업·사이트 어댑터 소스를 공유하며, 별도 모델이나 외부 번역 서버를 띄우지 않는다. Chromium은 `manifest.json`, Firefox는 `manifest.firefox.json`을 사용한다.

현재 소스의 확장 버전은 `0.7.8`다. 아래 웹 메신저 읽기 번역은 아직 공개하지 않은 개발 변경이며, 현재 공개된 Windows 앱 `0.7.2-beta`는 새 설정과 전용 처리 경로를 지원하지 않는다. 이 기능의 심사·사용에는 새 호환 본체가 필요하다. 해당 본체를 배포한 뒤 제출 자료의 다운로드 링크를 갱신해야 하며, 이 문서는 아직 존재하지 않는 새 버전이나 배포 URL을 지정하지 않는다.

## 동작 구조

```text
지원 웹사이트 또는 사용자가 켠 일반 웹사이트의 보이는 문단
  → 확장 콘텐츠 스크립트가 허용된 텍스트 노드만 추출
  → Native Messaging
  → 설치된 NudeNyang 실행 파일의 호스트 모드
  → 실행 중인 Windows 앱의 인증된 127.0.0.1 브리지
  → 웹 전용 문맥 관리 경로와 기존 표시 번역 워커·현재 선택 모델
  → 원래 텍스트 노드에 결과 적용
```

확장의 백그라운드는 페이지 요청마다 Native Messaging 호스트를 다시 실행하지 않고 브라우저 세션의 연결 하나를 재사용한다. 연결이 끊기면 대기 중인 요청을 오류로 정리하고 다음 요청에서 자동으로 다시 연결한다. 긴 문서에서 문단별 프로세스 시작 비용이 누적되지 않으며 Chrome·Whale의 확장 서비스 워커와 Firefox의 이벤트 백그라운드도 같은 연결 정책을 사용한다.

확장은 부모 요소의 `innerHTML`이나 `textContent`를 통째로 바꾸지 않는다. 한 문단 안의 인라인 텍스트 노드를 같은 문맥으로 묶어 번역한 뒤 각 노드 값만 바꾼다. 링크, 강조, 목록, 제목과 문단의 DOM 구조는 그대로 남으며, 끄기 또는 `이 페이지 원문으로 복원`을 누르면 기록한 원문을 정확히 되돌린다. 한 번의 요청 한도 안에 들어가는 일반 문단은 링크와 각주가 많아도 배치의 남은 항목·문자 수에 맞춰 나누지 않고 다음 요청으로 통째로 넘겨 문맥을 보존한다. 링크의 표시 문구가 URL·도메인·이메일 주소 자체인 경우에는 목적지를 식별할 수 있도록 그 링크 문구를 원문으로 유지한다. 일반 단어나 문장으로 표시된 링크는 문단 문맥과 함께 번역한다.

일반 웹페이지에서 번역을 끄면 원문과 이미 완료된 번역문을 페이지 메모리에 함께 보존한다. 다시 켤 때 원문이 바뀌지 않은 문단은 번역 엔진이나 스크롤 유휴 대기열을 거치지 않고 저장된 번역문을 즉시 다시 표시하며, 그사이에 추가되거나 내용이 바뀐 문단만 새로 번역한다. 페이지 이동 또는 목표 언어 변경 때는 이전 페이지·언어의 번역 기록을 폐기해 오래된 결과가 다른 문단에 붙지 않도록 한다. 웹 메신저의 대화 전환·종료·동의 철회 시 사본 폐기 규칙은 아래 별도 절을 따른다.

Discord와 웹은 같은 모델 런타임과 공급자 연결을 공유하지만 수집·문맥·스케줄링 상태는 분리한다. Discord 메시지는 기존처럼 즉시 처리하고, 웹페이지는 스크롤이 잠시 멈춘 뒤 보이는 문단을 모아 처리한다. 로컬 모델로 긴 웹 문단을 번역할 때는 문장 경계 기준의 짧은 추론 조각으로 나누고 조각 사이에 브라우저 렌더링 시간을 양보한 뒤, 문단 전체 결과가 준비되었을 때만 DOM에 적용한다. 따라서 링크와 각주가 많은 문단의 레이아웃을 보존하면서도 모델이 GPU를 장시간 연속 점유하는 현상을 줄이며, 이 웹 전용 분할 정책은 Discord 번역 단위에 영향을 주지 않는다.

웹 번역은 Windows 앱 연결과 선택한 번역 모델의 준비 상태를 확인하며 Discord 데스크톱 연결 여부에는 의존하지 않는다. Discord가 실행 중이 아니거나 연결에 실패해도 확장이 앱에 연결되면 웹 세션이 독립적으로 모델 준비를 요청하고 번역을 계속한다. Native Messaging 상태 응답은 앱 연결, 모델 준비와 Discord 연결을 서로 다른 값으로 전달하며 확장 팝업은 Discord 연결 상태를 웹 번역의 차단 조건으로 사용하지 않는다. 웹 메신저에는 별도로 본체의 기능 허용·브라우저 프로필의 동의·로컬 모델 조건을 모두 적용한다.

## 설정 위치

### 브라우저 연결 안내 — 미공개 개발 변경

`웹 번역` 설정 상단에 Chrome·Whale·Firefox 연결 목록을 항상 표시한다. 하나를 연결해도 화면을 닫거나 다른 브라우저를 숨기지 않으며, 각각의 설치 대기·오류·연결 확인 상태를 독립적으로 유지한다. 연결을 완료해도 체험 페이지를 열거나 번역을 자동으로 시작하지 않는다. 사용자가 원하는 사이트에서 확장을 눌러 시작하며, 연결된 브라우저의 `스토어 열기`로 다른 프로필에도 설치할 수 있다.

- `연결`은 설치된 브라우저의 App Paths 또는 표준 설치 경로를 확인하고 **선택한 브라우저**로 고정된 공식 스토어 상세 페이지를 연다. 기본 브라우저로 대신 열거나 브라우저 프로필·방문 기록을 읽지 않는다. 확장 추가와 권한 승인은 사용자가 스토어에서 직접 수행한다.
- Chrome: <https://chromewebstore.google.com/detail/nudenyang-web-translator/kpagdcdgomdlnnphakjakpodmgnhgaia>
- Whale: <https://store.whale.naver.com/detail/afnknfkmicnmdcfgmddelbpmkadcgifk>
- Firefox: 사용자가 2026-08-28에 AMO 심사 미통과 상태임을 확인했다. <https://addons.mozilla.org/firefox/addon/nudenyang-web-translator/>는 승인 후 사용할 주소이며, 현재는 `스토어 심사 중` 안내와 비활성 설치 버튼을 표시한다. 이미 설치한 개발 확장의 연결 확인은 허용한다. 승인 뒤 `browser_setup.rs`의 Firefox 스토어 경로를 활성화해야 한다.
- `연결 확인`은 현재 실행 파일의 Native Messaging 등록을 다시 구성하고 새 응답을 기다린다. 확장을 강제로 설치·재설치하지 않으며 다른 브라우저를 종료하거나 설정·개인정보 동의를 바꾸지 않는다. 등록을 찾지 못했던 확장은 브라우저에서 팝업을 열어 다시 연결할 수 있다.
- 확장은 설치·업데이트·브라우저 시작과 창 활성화 때 가벼운 `connectionPing` 요청을 보낸다. `alarms` 권한으로 1분 간격의 재확인도 예약하므로, 본체를 나중에 실행하거나 재시작한 경우에도 재연결한다. 요청에는 브라우저 종류·확장 버전과 연결 요청 식별자만 포함하며 페이지 내용·주소·프로필 이름을 보내지 않는다. 이 요청은 모델 준비나 Discord 연결을 요구하지 않는다.
- 앱은 최근 4분 내 응답만 연결 상태로 표시한다. 무응답·휴면·브라우저 종료는 `연결 확인 대기`로 처리하며 확장 미설치로 단정하지 않는다. 수동 확인은 시작 전 기록을 성공으로 재사용하지 않고, 새 응답이 없으면 90초 뒤 팝업에서 확인하도록 안내한다. 브라우저가 알람을 늦추거나 긴 번역 요청을 처리 중이면 확인도 늦어질 수 있다.
- 목록은 브라우저 종류별 최근 연결을 표시하며 모든 프로필의 설치 여부를 보장하지 않는다. 확장은 설치한 프로필에서만 사용할 수 있다는 안내를 유지하고, 연결 상태와 모델 준비·웹 번역 사용 여부를 분리한다.

### 웹 번역 설정

Windows 앱의 `웹 번역` 탭이 저장 설정의 기준이다.

- 웹 번역 전체 사용 여부와 기본 목표 언어
- 처리 모드: `자동`, `반응 우선`, `사용량 절약`
- 외부 번역기의 페이지별 전송 문자 보호 한도
- `웹 메신저 읽기 번역` 허용 여부: 기본 꺼짐이며 로컬 AI에서만 사용 가능
- Chrome·Whale·Firefox 연결 상태와 확장 버전
- 사이트별 `이 사이트 자동 번역`, `직접 시작`, `번역 안 함` 정책

저장한 사이트가 6개 이상이면 호스트 이름 검색을 표시하고, 목록은 약 6개 행 높이 안에서 제품형 스크롤바로 탐색한다. 정책 선택은 앱의 다른 설정과 같은 커스텀 셀렉트 디자인과 키보드 조작 규칙을 사용한다.

확장 팝업은 현재 탭에서 자주 쓰는 기능만 제공한다. 현재 탭 켜기·끄기, 이 페이지에만 적용할 목표 언어, `이 사이트 자동 번역`, 원문 복원, 페이지 요청 수와 전송 문자 수를 확인할 수 있다. `웹 번역 설정 열기`를 누르면 Windows 앱의 해당 탭이 열린다. 지원 메신저에서는 별도의 개인정보 안내를 열어 해당 브라우저 프로필의 동의를 저장하거나 철회할 수 있으며, 본체 설정 꺼짐·동의 필요·외부 모델 선택·열린 대화 없음 상태를 구분하여 안내한다.

웹 번역 전환키 또는 상단 토글로 선택한 번역 상태는 현재 탭이 닫힐 때까지 유지된다. 같은 탭에서 링크를 열거나 주소가 바뀌어도 켠 상태는 계속 켜지고, 끈 상태는 계속 꺼진다. 이 탭의 명시적인 선택은 사이트 자동 번역 기본값보다 우선하지만, Windows 앱의 웹 번역 전체 끄기와 `번역 안 함`, 로그인·결제 등 민감 경로의 차단은 항상 우선한다. 개인 메시지는 범용 경로에서 계속 차단하며, 아래 전용 경로의 동의·설정·모델 조건을 모두 만족할 때만 제한적으로 처리한다. 탭 상태나 자동 번역 정책은 이 조건을 대신하지 않는다. `이 사이트 자동 번역`은 앞으로 해당 사이트를 새 탭이나 새 방문으로 열 때 자동 시작할지를 저장하는 정책이다.

링크가 별도 탭이나 브라우저 팝업 창을 열면, 새 탭 자체에 저장된 선택이 없는 경우에만 같은 HTTP/HTTPS 출처의 부모 탭에서 명시적으로 선택한 켜기·끄기를 상속한다. 출처는 프로토콜·호스트·포트가 모두 같아야 하며, 부모의 출처를 확인할 수 없거나 다른 사이트로 열린 경우에는 상속하지 않는다. 사이트 자동 번역 기본값은 부모의 명시적인 선택으로 취급하지 않는다. 새 탭에서 직접 바꾼 상태와 민감 경로·사이트 차단 정책은 계속 우선하며, 비동기 상태 조회나 브라우저 백그라운드 재시작 때문에 최신 선택이 이전 값으로 덮어써지지 않도록 탭별 저장 작업을 순서대로 처리한다.

X의 `더보기`처럼 이미 보이는 문단의 내용을 동적으로 펼치거나 교체하는 동작은 기존 화면 진입 관찰을 기다리지 않는다. 바뀐 현재 문단을 일반 스크롤 대기열보다 먼저 처리해, 피드의 다른 게시물 뒤에서 번역이 지연되지 않도록 한다.

페이지 언어 선택은 새로 고칠 때까지 유지되는 일시 설정이다. 사이트 정책과 Windows 앱의 설정은 저장되며 Chrome, Whale과 Firefox가 같은 Windows 앱 설정을 함께 사용한다. 메신저 개인정보 동의는 본체 설정과 달리 각 브라우저 프로필에 따로 저장한다.

메신저 설정을 켰는데 팝업에 동의 필요 안내가 표시되면, 안내 바로 아래의 `개인정보 안내 확인` 버튼을 누른다. 열린 안내에서 체크박스를 선택하고 명시적으로 동의하면 원래 대화 탭으로 돌아가 새로고침 없이 번역을 시작한다. Firefox에서는 이 동작에서 개인적 커뮤니케이션 권한도 허용해야 한다. 하단의 동의 관리 링크는 자동 시작 없이 안내·철회 화면만 연다. 본체 토글이나 사이트 자동 번역은 브라우저 동의를 대신하지 않는다.

동의 화면에는 원래 탭 번호와 임의의 대화 문맥 식별자만 전달하며 실제 대화 URL·참여자·메시지는 전달하지 않는다. 동의 후 시작은 해당 대화에만 적용하고 기존 사이트 정책이나 탭 전체의 저장된 켜짐 상태를 바꾸지 않는다. 대화 이동·탭 닫힘·동의 철회·명시적 끄기 뒤에는 이전 시작 요청을 적용하지 않으며, 시작 직전에 본체 설정·로컬 모델·브라우저 동의를 다시 확인한다. 숨겨진 대화 탭은 화면으로 돌아오기 전까지 메시지를 수집하지 않는다.

## 인터페이스 언어

확장 팝업은 Windows 앱의 `인터페이스 언어` 설정을 기준으로 표시한다. Native Messaging 상태 응답은 저장된 `uiLanguage`와 Windows 시스템 언어까지 해석한 `resolvedUiLanguage`를 함께 전달하며, 팝업은 실제 적용 언어를 우선 사용한다. 앱에서 명시적으로 언어를 선택하면 다음에 팝업을 열 때 같은 언어가 적용되고, `Auto (System)`은 Windows 사용자 로케일을 메인 앱과 확장에서 같은 28개 지원 언어 코드로 해석한다. 앱에 연결하기 전에는 브라우저 표시 언어를 임시 대체값으로 사용하며 지원하지 않는 언어는 영어로 표시한다.

팝업 문구는 메인 앱의 `web/i18n.mjs`와 `web/ui-locales.mjs`를 단일 번역 원본으로 사용한다. `npm run extension:locales`가 팝업 전용 최소 사전과 Chrome·Whale·Firefox 표준 `_locales` 메타데이터를 생성한다. 확장 관리 화면의 이름·설명은 실행 중인 앱이 바꿀 수 없으므로 브라우저 표시 언어를 따르고, 팝업과 실행 중 오류 안내는 앱의 인터페이스 언어를 따른다.

## 개발 설치

본체와 확장은 호환 가능한 제품 세대를 바로 알아볼 수 있도록 Major·Minor 버전만 맞춘다. Patch 버전은 Windows 앱과 브라우저 확장의 수정·심사 주기에 따라 서로 독립적으로 올린다. `0.7.x`라는 같은 제품 세대가 이후 추가된 모든 기능의 사용 가능성을 보장하는 것은 아니다. 웹 메신저처럼 새 본체 지원이 필요한 기능은 상태 응답의 기능 허용 값까지 확인하며, 구버전이 해당 값을 제공하지 않으면 사용하지 않는다. 확장 수정만을 이유로 본체의 Patch 버전을 억지로 맞추지 않는다. 호환성이 깨지는 변경에는 두 구성요소의 Major 또는 Minor를 함께 올린다. Windows 앱의 시험 배포에는 `-beta` 접미사를 사용하고, 브라우저 매니페스트에는 숫자 버전만 기록한다.

1. 최신 NudeNyang Windows 앱을 한 번 실행한다.
2. 실행 파일에 `--register-browser-native-host`를 붙여 한 번 실행한다. 정식 설치본은 설치 과정에서 이 등록을 자동으로 수행한다.
3. Chrome은 `chrome://extensions`, Whale은 `whale://extensions`를 연다.
4. 개발자 모드를 켜고 `압축해제된 확장 프로그램을 로드`에서 저장소의 `extension` 폴더를 선택한다.
5. Firefox 개발 패키지는 `npm run extension:firefox`로 만든다. 이 명령은 메인 앱 사전에서 확장 언어 파일도 다시 생성한다.
6. Firefox에서 `about:debugging#/runtime/this-firefox`를 열고 `임시 부가 기능 로드`에서 `dist/firefox-extension/manifest.json`을 선택한다.
7. Chrome과 Whale은 브라우저를 완전히 종료했다가 다시 시작한다. Firefox 임시 설치는 종료 시 제거되므로 개발 검증 중에는 Firefox를 재시작하지 않는다.

개발 중 확장 관리 화면에서 확장을 다시 로드하면 이미 열려 있던 페이지의 이전 콘텐츠 스크립트는 무효화된다. 이전 스크립트는 무효화를 감지하면 남은 번역 대기열과 DOM 관찰을 종료하고 적용된 텍스트를 원문으로 복원한다.

확장 업데이트·재로드 뒤 이미 열려 있던 일반 HTTP/HTTPS 탭에 새 콘텐츠 스크립트 수신자가 없으면, 백그라운드가 사용자가 다시 활성화한 탭의 연결을 조용히 확인한다. 연결이 없을 때만 최신 콘텐츠 스크립트를 다시 삽입하고 탭에 저장된 번역 상태를 복원한다. 팝업 조작과 보조 단축키도 같은 복구 경로에서 원래 요청을 한 번 자동 재시도하므로 보통 페이지 새로고침이 필요하지 않다. 브라우저 내부 페이지처럼 스크립트 삽입이 금지된 화면에서는 복구를 시도하지 않는다.

페이지 연결 확인·설정·상태·토글 메시지는 최상위 프레임(`frameId: 0`)에만 전달한다. 하위 프레임의 응답이 페이지 응답을 대신하지 않으며, 정적 콘텐츠 스크립트 로드와 자동 복구 주입이 겹쳐도 문서별 실행기는 하나만 유지한다. 초기 앱·탭 상태를 읽는 동안 들어온 토글도 순서대로 반영해 늦게 도착한 초기 상태가 사용자 선택을 되돌리지 않도록 한다.

이미 열린 페이지를 복구할 때는 일반 콘텐츠 스크립트와 별도로 제한된 임베드 제목 스크립트도 프레임에 다시 주입한다. 이 스크립트는 정확한 YouTube 임베드 하위 프레임인지 먼저 검사하며, 그 밖의 프레임에서는 DOM 수집이나 번역 요청 없이 종료한다. 같은 버전의 정상 실행기가 이미 있으면 중복 초기화하지 않는다. 백그라운드 워커가 재시작되어 프레임 등록 목록이 사라져도 부모의 끄기·언어 변경 신호는 같은 탭에 전달되며, 임베드는 부모의 승인을 다시 확인한다.

Chromium 확장은 스토어 제출본과 개인 테스트본의 ID를 분리한다. `npm run extension:chromium`은 Chrome 웹 스토어 ID `kpagdcdgomdlnnphakjakpodmgnhgaia`용 ZIP을 만들고 manifest의 `key`를 제거한다. `npm run extension:personal`은 `dist/chromium-personal-extension`에 기존 개인용 ID `bdkkgjjmocmdknffadjgbljmnhdcchjl`을 유지하는 압축해제 확장을 만든다. 두 공개 키와 ID는 `extension/chromium-identities.json`에서 함께 검증한다. Windows 앱의 Chromium `allowed_origins`는 이 두 ID와 Whale 스토어 ID `afnknfkmicnmdcfgmddelbpmkadcgifk`를 명시적으로 허용한다. Firefox Add-on ID는 `web-translator@nudenyang.github.io`로 고정되어 있다. Windows 앱은 Chromium의 `allowed_origins`와 Firefox의 `allowed_extensions`를 별도 호스트 매니페스트로 등록하며 와일드카드나 임의의 확장 ID를 허용하지 않는다.

`release/browser-extension/NudeNyang-Web-Translator-Firefox-<version>.xpi`는 Mozilla 제출과 개발 검증을 위한 패키지다. 일반 Firefox 사용자가 영구 설치하는 XPI는 Mozilla 서명이 필요하다. 서명되지 않은 로컬 패키지는 `about:debugging`의 임시 부가 기능으로 검증하며, 공개 배포는 AMO 검토 또는 자체 배포용 서명 후 진행한다.

`release/browser-extension/NudeNyang-Web-Translator-Chromium-<version>.zip`은 Chrome 웹 스토어와 Whale 스토어에 올리는 패키지다. 개발용 manifest의 `key`는 포함하지 않으며 스토어가 발급한 항목 ID를 확인한 뒤 Native Messaging 허용 목록을 동기화한다.
스토어 설치 검사가 운영체제와 화면 배율에 관계없이 같은 아이콘 규격을 확인할 수 있도록 manifest의 각 아이콘 슬롯은 선언한 숫자와 실제 PNG 픽셀 크기를 일치시킨다.

Windows 앱이 꺼져 있거나 호스트 등록이 없으면 확장 팝업에 연결 오류가 표시된다. 앱을 실행한 뒤 페이지를 새로 고치거나 확장 토글을 다시 켜면 된다. 모델을 처음 준비하는 동안에는 확장이 잠시 기다렸다가 재시도한다.

## 단축키

- `F4`(기본값): 지원 웹페이지나 확장 팝업에 포커스가 있을 때 현재 탭의 번역과 원문을 전환한다. 메인 앱의 `편의 기능` 단축키 카드에서 다른 키 조합으로 바꾸거나 사용하지 않도록 설정할 수 있다.
- `Ctrl+Shift+L`(기본값): Chrome, Whale과 Firefox의 확장 명령으로 등록되는 보조 단축키다. 각 브라우저의 확장 프로그램 단축키 설정에서 다시 지정할 수 있다.

주소창, 브라우저 설정 화면, 확장 관리 화면과 지원하지 않는 사이트에서는 웹 번역 전환키가 동작하지 않는다. 기능 키를 웹 번역 전환키로 선택했고 노트북의 기능 키가 미디어 동작으로 설정된 경우에는 키보드 설정에 따라 `Fn` 입력이 필요할 수 있다.

전용 어댑터가 없는 일반 사이트는 범용 어댑터를 사용한다. 범용 어댑터는 기본적으로 페이지를 열었을 때 자동으로 텍스트를 수집하지 않으며, 사용자가 해당 탭에서 웹 번역 전환키를 누르거나 팝업 토글을 켠 뒤에만 현재 화면과 가까운 문단을 번역한다. 이 상태는 탭을 닫을 때까지 페이지 전환 뒤에도 이어진다. Windows 앱이나 팝업에서 사이트를 `이 사이트 자동 번역`으로 저장하면 새 탭이나 다음 방문부터 자동으로 시작하고, `번역 안 함`으로 저장하면 전용 지원 사이트도 시작하지 않는다. 로그인·계정·결제·주문·개인 메시지처럼 민감한 경로의 범용 차단은 탭 상태와 사이트 정책보다 우선한다. 웹 메신저 예외는 별도의 전용 어댑터와 개인정보 조건을 거치며 범용 수집기로 대체하지 않는다.

범용 수집기는 먼저 제목·문단·목록·인용문·표처럼 의미가 명확한 HTML 요소를 문맥 단위로 사용한다. 이어서 공개 본문의 `div`·`span`·링크처럼 레이아웃 요소로 만든 읽기 블록을 보완한다. 알려진 본문 ID나 자식 요소가 없는 구조에만 의존하지 않고, 직접 텍스트에 줄바꿈·강조·링크가 섞인 설명도 같은 문맥으로 묶는다. 이미 의미 있는 문단 안에 들어 있는 인라인 요소는 별도 블록으로 다시 수집하지 않아 문장이 잘게 쪼개지지 않는다. 입력 폼·버튼·탐색·대화상자·코드·가격·쿠키 동의·민감 경로 제외 규칙은 이 보완 수집에도 동일하게 적용한다.

X의 긴 형식 기사는 대화상자 형태로 열릴 수 있지만, 기사 제목과 문단으로 식별된 블록만 대화상자 제외 규칙을 우회한다. 작성 UI, 작성자 표시 이름과 핸들, 동작 버튼 및 다른 대화상자 내용은 계속 제외한다. 기사 안의 코드 블록도 공통 코드 제외 규칙을 유지한다.

DLsite 전용 어댑터도 이 범용 공개 본문 규칙을 공유하므로 제목·문단·목록·표 셀뿐 아니라 본문 안의 독립형 안내와 CTA를 처리한다. 왼쪽 카테고리처럼 본문 밖에 배치된 목록과 분리된 공개 탐색 링크는 전용 범위로 보완한다. 공개 상단 영역은 일반 웹페이지에서 제외하는 `header`와 `nav` 안에 있으므로, 고정 소개 문구·언어·관련 서비스와 즐겨찾기·장바구니·구매 작품·계정·가이드의 고정 메뉴 이름, 그리고 계정·마이페이지·찜·장바구니·주문·결제·로그인 주소가 아닌 공개 링크만 명시적으로 번역한다. 포인트·쿠폰의 숫자, 계정의 펼침 메뉴, 검색 입력값과 이미지 배너 안의 글자는 텍스트 노드 번역 대상에 포함하지 않는다.

EISYS 기업 사이트 전용 어댑터는 공개 기업 정보와 사업·뉴스 본문을 범용 문서 범위로 처리한다. 상단 및 하단 탐색 메뉴는 일반 사이트의 `header`, `nav`, `footer` 제외 규칙을 정확한 공개 선택자에 한해서만 우회하며, 입력 폼과 대화상자 같은 상호작용 영역은 계속 제외한다.

TAKARA TOMY 전용 어댑터는 기업·상품·카드 공개 페이지의 본문과 탐색 문구를 처리한다. 카드 검색 폼에서는 고정된 조건 이름과 검색·초기화 안내 문구만 허용하며, 사용자가 입력한 검색어, 폼 값, 체크 상태는 읽거나 바꾸지 않는다. CSS나 `hidden`·`aria-hidden` 속성으로 뒤늦게 펼쳐지는 허용 메뉴도 표시 상태가 바뀌면 다시 수집한다. 가려진 메뉴나 임의의 계정 폼까지 미리 번역하는 방식은 사용하지 않는다. 별도 브라우저 팝업 창의 카드 상세는 일반 최상위 문서로 처리하며, 카드 그림에 인쇄된 텍스트는 OCR 대상에 포함하지 않는다.

ShoPro의 `www.shopro.co.jp/anime/` 공개 페이지에서는 기존 범용 본문에 더해 실제 헤더 메뉴 구조로 식별된 링크 문구만 허용한다. 모바일 메뉴가 CSS로 펼쳐지면 보이는 항목을 다시 확인하며, 링크 목적지와 메뉴 버튼의 동작은 바꾸지 않는다. 처음 방문한 페이지를 자동으로 켜는 정책은 추가하지 않는다. 사용자가 탭에서 번역을 켜거나 해당 사이트의 자동 번역을 저장한 경우에만 동작한다.

일반 페이지 콘텐츠 스크립트는 최상위 문서에서만 실행한다. 예외적으로 `https://www.youtube.com/embed/*`와 `https://www.youtube-nocookie.com/embed/*`에는 `embedded-title.js`를 별도로 주입해 화면에 표시되는 영상 제목 DOM만 처리한다. 이 제한 스크립트는 부모 문서의 번역 활성 상태와 페이지 정책·가시성을 확인받은 뒤 제목을 요청하며, 부모 문서와 목표 언어·페이지별 전송 한도를 공유한다. 부모가 꺼져 있거나 차단된 페이지, 숨겨진 프레임은 독립적으로 번역을 시작하지 않는다. 다른 출처의 iframe, 채널명, 영상 자막·음성·이미지 내용은 수집하지 않는다. 임베드 제목 자체는 기존 HTTP/HTTPS 호스트 권한과 일반 웹 데이터 범주 안에서 처리한다. 웹 메신저 기능에 추가한 Firefox의 선택 데이터 고지 `personalCommunications`는 이 임베드 기능과 별개다. 메신저 전용 문맥에서는 임베드 번역을 허용하지 않는다.

한 문단 자체가 한 번의 요청 한도보다 크면 기존 텍스트 노드 경계에서만 요청을 나눠 누락을 방지한다. 일반 문단은 기존처럼 함께 처리하며, 원래 노드의 위치·줄바꿈·링크는 유지한다. 임베드 제목도 별도 엔진 호출이나 비용 한도를 만들지 않고 부모 페이지의 대기열에 합류한다. 연결 복구로 같은 제목 요청이 다시 들어오면 진행 중인 작업을 이어받아 중복 전송하지 않는다.

범용 권한은 `http://*/*`와 `https://*/*`에만 적용된다. Chrome·Whale·Firefox 내부 페이지, 로컬 파일과 다른 URL 스킴에는 주입하지 않는다. 브라우저는 이 범위 때문에 설치 또는 업데이트 시 모든 웹사이트의 데이터를 읽고 변경할 수 있다는 권한 경고를 표시할 수 있다. Firefox의 기존 필수 고지는 `websiteContent`와 `browsingActivity`이며 메신저에는 선택 고지 `personalCommunications`를 사용한다. 일반 웹 요청의 페이지 식별자는 프로토콜·호스트 이름·경로로 구성하고 쿼리 문자열과 해시를 포함하지 않는다. 메신저 요청은 실제 대화 주소 대신 아래의 임시 식별자를 사용한다. 실제 구현은 전체 HTML, 쿠키, 로그인 토큰이나 방문 기록 목록을 읽거나 전달하지 않는다.

사이트는 수시로 DOM 구조를 바꿀 수 있다. 어댑터 선택자가 맞지 않는 영역은 억지로 번역하지 않고 원문으로 남기는 것을 기본 실패 방식으로 삼는다. 일반적인 긴 페이지에서는 선택한 처리 모드에 따라 현재 화면 주변 약 120~240px의 문단을 우선 처리하고, 나머지는 스크롤로 가까워질 때 번역한다. 웹 메신저는 이 미리 읽기 여백을 사용하지 않고 현재 화면에 보이는 본문으로 한정한다. 문서 전체의 후보 블록은 위치를 하나씩 동기 계산하지 않고 브라우저의 화면 진입 관찰자에 등록하며, 실제 화면 근처에 들어온 문단만 번역 대기열에 넣는다. 스크롤 중에는 DOM 적용을 멈추고 140~700ms의 유휴 구간 뒤에 작업을 모은다. 번역 결과는 같은 문단의 모든 인라인 노드를 한 프레임에서 함께 바꾸며, 한 프레임에 최대 두 문단만 적용한다. 따라서 링크와 각주가 많은 위키 문단도 여러 프레임으로 갈라져 반복적인 레이아웃 계산을 일으키지 않는다. X·YouTube·BOOTH처럼 DOM을 자주 교체하는 화면에서는 중첩된 변경 범위를 한 번만 스캔하며, 모델 호출 직전에 끊어졌거나 화면에서 멀어진 작업은 폐기한다.

이 스케줄링 정책은 목표 언어와 무관하다. 외부 번역기를 선택하면 호출당 고정 프롬프트 비용을 줄이기 위해 로컬 모델보다 더 큰 배치를 우선한다. 번역 캐시는 목표 언어별로 분리되므로 처음 선택한 언어의 첫 페이지 번역은 기존 언어보다 느릴 수 있지만, 화면 밖 문단이나 사라진 DOM 때문에 콜드 캐시 비용이 불필요하게 커지지 않도록 제한한다. 같은 배치에 동일한 원문과 감지 언어가 반복되면 번역 엔진은 공급자 호출을 한 번만 수행하고 결과를 공유한다.

외부 번역기의 페이지별 보호 한도는 페이지에서 실제로 요청한 원문 문자 수를 기준으로 계산한다. 한도에 도달하면 새 문단 전송을 멈추고 이미 번역된 문단과 원문 복원 기능은 유지한다. `제한 없음`도 선택할 수 있지만 상용 AI의 과금·사용량 제한을 사용자가 직접 관리해야 한다. 로컬 모델은 이 문자 보호 한도의 영향을 받지 않는다.

## 웹 메신저 읽기 번역 — 개발 중

이 기능은 기존 Discord 데스크톱의 읽기·작성·전송 동작과 분리된 웹 전용 경로다. 이미 대화 화면에 표시된 메시지와 아래에 명시된 Discord 채널명·미리보기 텍스트를 번역하며, 메시지를 입력하거나 전송하는 기능을 제공하지 않는다. 아직 8개 서비스 모두에서 로그인한 실제 계정으로 실사용 검증을 마친 상태가 아니다. 어댑터·DOM 회귀 테스트는 구조와 보호 규칙을 검증하지만 각 서비스의 최신 실사용 화면 전체에 대한 지원 완료를 의미하지 않는다.

### 허용 조건과 서비스

다음 조건을 모두 만족해야 본문 추출과 번역 요청을 시작한다.

1. 본체의 웹 번역이 켜져 있고 `AppConfig.web_messenger_enabled`가 `true`여야 한다. 기본값은 `false`이며 상태 응답의 `webSettings.messengerEnabled`가 없거나 `true`가 아니면 차단한다.
2. 현재 브라우저 프로필에서 개인정보 안내를 읽고 명시적으로 동의해야 한다. `0.7.7`부터 Discord 채널명·미리보기 범위가 포함된 동의 버전 `2`만 허용하며 이전 버전 `1`은 자동 승격하지 않는다. 동의 버전은 `messengerConsentVersion`으로 브라우저 로컬 설정에 저장하며 본체 설정이나 다른 프로필의 동의로 대체하지 않는다.
3. Firefox에서는 별도 선택 권한 `personalCommunications`도 허용되어야 한다. 동의 버튼 동작에서 `permissions.request({ data_collection: ["personalCommunications"] })`를 호출하며, 취소·거부·나중의 권한 철회는 허용으로 처리하지 않는다.
4. 현재 공급자가 로컬 Hy-MT2 또는 TranslateGemma여야 한다. 외부 서비스가 선택되거나 숨은 외부 대체 경로가 있는 경우에도 차단한다.
5. HTTPS 최상위 문서의 지원 경로에서 현재 열린 대화를 하나로 안전하게 식별할 수 있어야 하고, 탭의 번역 상태와 사이트 정책이 허용해야 한다. 대화·본문이 숨겨져 있거나 구조를 식별하지 못하면 수집하지 않는다.

| 서비스 | 전용 범위 |
|---|---|
| X DM | `x.com`·`twitter.com`의 대화 경로 및 공개 화면에 열린 식별 가능한 DM 패널 |
| 웹 Discord | `discord.com`·`ptb.discord.com`·`canary.discord.com`에서 현재 열린 채널 또는 DM의 본문·링크 미리보기 텍스트, 서버 채널 화면에서는 현재 서버의 보이는 채널 이름 |
| WhatsApp Web | `web.whatsapp.com`의 현재 대화 |
| Telegram Web | `web.telegram.org`의 지원 웹 클라이언트에서 현재 열린 대화 |
| Messenger | `messenger.com`의 현재 대화 경로 |
| Slack | `app.slack.com`의 현재 채널·DM·스레드에서 식별되는 대화 |
| Microsoft Teams | `teams.microsoft.com`·`teams.live.com`·`teams.cloud.microsoft`의 현재 대화 |
| Google Messages | `messages.google.com`의 현재 웹 대화 |

`messenger-adapters.js`는 서비스·대화 구조와 허용된 텍스트 영역만 식별한다. DM 상대 목록·다른 서버의 채널 목록·작성자 이름·핸들·연락처·프로필, 작성창·입력값·초안·전송 UI, 첨부 파일·미디어·코드는 제외한다. 다른 대화를 자동으로 열거나 과거 메시지를 내려받지 않는다. 본문 자체에 개인정보가 포함되어 있으면 로컬 번역에는 포함될 수 있으며 자동 익명화를 보장하지 않는다. 이메일·미지원 메신저·계정·결제 등 기존 민감 경로의 범용 차단은 유지하고, 전용 수집에 실패해도 범용 수집으로 우회하지 않는다.

### Discord 채널명과 링크 미리보기 (`0.7.7`)

현재 서버의 채널 링크(`channels___*`와 같은 서버의 `/channels/<server>/<channel>` 경로가 일치하는 항목) 안의 시각적 이름과 열린 채널 제목만 추가한다. 접근성 중복 이름 때문에 사용되는 `aria-hidden`은 이 이름의 확인된 래퍼 한 곳에만 예외를 두며, 숨김·접힘·화면 밖·입력·대화상자 영역은 계속 제외한다. DM 상대 이름, 카테고리명, 다른 서버의 채널명은 수집하지 않는다. 메시지가 없는 열린 서버 채널도 안전하게 식별되면 이름을 번역한다.

현재 메시지 목록 안의 Discord 임베드 제목·설명·필드 이름·값을 데스크톱 어댑터와 같은 의미 단위로 선택한다. 작성자·제공자·푸터·첨부·이미지·URL은 제외하며 링크 대상 페이지를 내려받거나 이미지를 OCR하지 않는다. 모든 추가 텍스트는 기존 로컬 AI 전용 임시 메모리 경로와 대화 전환·철회 정리를 공유한다.

동의 범위가 넓어지므로 콘텐츠 스크립트·백그라운드·본체 모두 버전 `2`를 요구한다. 기존 동의와 본체 활성화 설정만으로 새 범위를 켜지 않으며 갱신된 안내에서 직접 동의해야 한다. 28개 언어 안내를 함께 갱신한다. Discord 회귀 데이터는 기존 데스크톱 선택자를 기준으로 합성했고 실제 계정 데이터는 포함하지 않았다. 실제 웹 Discord 화면의 동작은 확장 재로드 뒤 별도 확인이 필요하다.

### 요청과 사본의 수명

`0.7.8`은 X 가상 스크롤에서 첫 메시지가 추가·제거될 때 다른 대화로 오인해 전체 번역을 복원하던 문제를 수정한다. 명시적인 `/i/chat/<conversation>` 또는 `/messages/<conversation>` 경로의 새 X 채팅에서는 경로·대화 패널·메시지 스크롤러를 식별 기준으로 사용한다. 잠깐 비는 가상 목록도 같은 패널이면 유지하되, 대화 경로·패널·스크롤러가 바뀌거나 사라지면 사본과 이전 요청을 정리한다. 대화 경로가 없는 공개 DM 서랍에는 이 예외를 적용하지 않는다.

같은 X 대화에서 이미 번역한 연결된 메시지가 스크롤로 화면 밖에 나간 경우, 주기적인 상태 갱신으로 원문을 복원하지 않고 기존 메모리 상태만 유지한다. 이때 화면 밖 텍스트를 다시 읽거나 번역을 요청·적용하지 않는다. 숨김·입력·작성자 영역으로 재사용된 요소와 연결이 끊긴 요소는 보존 대상이 아니며, 대화 이동·동의 철회·명시적 OFF의 정리 규칙은 유지한다. 추가 수집 범위나 동의 변경은 없고 동의 버전은 `2`를 유지한다. 합성 DOM에서 첫 행 변경·빈 목록·상태 갱신과 보호 경계를 검증했으며 실제 Whale 스크롤 결과는 재로드 후 별도 확인이 필요하다.

X의 새 채팅 화면에서는 `dm-conversation-panel` → `dm-conversation-content` 안의 `dm-message-scroller[role="log"]`를 대화 영역으로 식별하고, 그 안의 `role="article"` → `message-text-*` → `span[dir="auto"]`만 본문 후보로 선택한다. 목록이 있는 `dm-inbox-panel`, 전체 `dm-container`, 범용 `role="log"`로 수집 범위를 넓히지 않는다. 말풍선에 함께 들어 있는 시간·상태·반응 UI는 본문 선택에 포함하지 않으며 화면 밖으로 잘린 메시지도 수집하지 않는다. 기존 X DM 구조도 유지하되 서로 다른 대화 영역이 동시에 보이면 형식과 관계없이 차단한다.

이 수정은 사용자가 제공한 Whale 확장 `0.7.5`의 실패 화면과 Elements 구조 캡처를 근거로 한다. `0.7.6` 회귀 테스트에는 해당 구조와 합성 본문·식별자만 사용하며 실제 DM 내용을 복사하지 않았다. 동의·자동 번역·스크롤 경계·대화 이동·철회는 가상 DOM에서 검증하며, 수정본의 실제 Whale 대화 번역 성공 여부는 확장 재로드 후 별도 확인이 필요하다. X 구조 수정 자체는 동의 저장 방식·권한·로컬 AI 전용 처리·디스크 미저장 원칙을 변경하지 않는다. 후속 `0.7.7`의 동의 버전 변경은 위 Discord 범위 추가에 따른 것이다.

메신저 요청은 `privateContext: { service, consentVersion }`와 `messenger:<service>:<random-id>` 형식의 `pageId`를 사용한다. 실제 대화 URL·대화 ID·참여자 목록은 요청 식별자에 넣지 않는다. 대화 전환 감지에 사용하는 경로·해시와 DOM 식별 정보는 콘텐츠 스크립트 안에만 유지한다. 백그라운드는 송신 확장·최상위 탭·서비스 출처·동의·본체 설정·로컬 공급자를 다시 검증한 뒤 Native Messaging으로 전달한다.

확장이 관리하는 원문·번역 사본은 현재 대화의 메모리에만 유지한다. 대화 전환·종료·동의 철회 때 사본과 대기 작업을 폐기하고 이전 대화에서 늦게 도착한 결과를 무시한다. 본체 기능을 끄거나 외부 공급자로 바꾸는 경우에도 새 요청을 차단하고 현재 사본을 정리한다. 이는 사이트 원문이나 서버 기록을 삭제하는 기능이 아니다.

Windows 본체는 메신저 요청 동안만 사용하는 `TranslationCache::in_memory`와 별도의 감지·문맥 상태로 처리한다. 일반 번역의 메모리·SQLite 캐시를 조회하거나 갱신하지 않으며, 요청이 끝나면 원래 일반 번역 상태를 복원한다. 대화 본문·번역문을 디스크 캐시·번역 기록·본문 로그에 저장하지 않는다. 저장되는 동의 기록과 설정은 대화 내용과 구분한다. 이미 진행 중인 추론이 즉시 중단되거나 그 메모리가 즉시 소거된다는 뜻은 아니다.

모델 요청의 `cache_prompt=false`는 프롬프트 캐시 재사용을 제한한다. 모델 런타임은 다른 번역과 공유하므로 별도의 격리된 프로세스나 RAM·VRAM·모델 KV 캐시의 즉시 물리 소거를 보장하지 않는다. 운영체제와 런타임이 관리하는 사본의 안전한 삭제까지 보장하지 않으며, 이 한계는 개인정보 고지에도 명시한다.

## 개인정보와 데이터

- 전용 지원 사이트의 허용 영역 또는 사용자가 직접 켠 일반 사이트에서 화면에 나타난 텍스트만 추출한다.
- 입력창, 결제, 주문, 계정, 코드 영역은 추출하지 않는다. 개인 메시지는 위의 명시적 동의를 받은 전용 읽기 경로에 한해서만 처리한다.
- 일반 웹 요청은 허용 텍스트와 현재 페이지의 프로토콜·호스트 이름·경로를 Windows 앱에 전달하며 쿼리 문자열과 해시는 제외한다. 메신저는 실제 대화 주소 대신 임의의 임시 대화 식별자를 전달한다.
- 페이지 HTML, 쿠키, 로그인 토큰, 방문 기록 목록은 읽거나 전달하지 않는다.
- 사이트별 정책에는 호스트 이름과 사용자가 선택한 동작만 PC의 설정에 저장한다.
- 앱 진단 로그에는 웹페이지 본문과 번역 프롬프트를 기록하지 않는다.
- 로컬 모델을 선택하면 텍스트는 PC 밖으로 나가지 않는다.
- 일반 웹 번역에서는 DeepL이나 구독형 외부 번역기를 선택하면 추출된 허용 영역 텍스트가 해당 공급자에게 전달된다. 이 경계는 Discord 표시 번역과 같다. 메신저 본문은 외부 번역기로 전달하지 않는다.
- Firefox는 기존 필수 `websiteContent`·`browsingActivity`와 별도 선택 `personalCommunications`를 고지한다. Chrome 제출 자료에도 웹사이트 콘텐츠·웹 기록·개인적인 커뮤니케이션 처리 범위를 명시한다. 상세 기준은 `PRIVACY.md`와 `docs/BROWSER_STORE_PRIVACY.md`를 따른다.

## 검증

DOM 회귀 테스트에는 개발 의존성 `jsdom 30.0.1`을 사용한다. Node.js `^22.22.2`, `^24.15.0` 또는 `>=26.0.0` 환경에서 먼저 `npm ci`로 잠금 파일의 의존성을 설치한다. jsdom은 테스트 전용이며 배포하는 확장 ZIP·XPI의 실행 코드에는 포함하지 않는다. 라이선스는 `THIRD_PARTY_NOTICES.md`에 기록한다.

```powershell
npm ci
npm run test:extension
cargo test --manifest-path src-tauri/Cargo.toml browser_translation
cargo test --manifest-path src-tauri/Cargo.toml browser_bridge::tests
```

다음은 Chrome, Whale과 Firefox에서 수행할 실브라우저 검증 항목이다. 목록의 존재는 검증 완료 기록이 아니며, 특히 새 메신저 기능의 8개 서비스 로그인 실사용 검증은 아직 완료하지 않았다.

1. 확장 팝업이 Windows 앱의 버전·모델·대상 언어를 읽는지 확인한다.
2. 한 문단에 링크와 굵은 글자가 섞인 테스트 문단을 번역한다.
3. 요소 구조와 링크 목적지가 그대로인지 확인한다.
4. 원문 복원을 누르고 모든 텍스트가 정확히 되돌아오는지 확인한다.
5. GitHub 코드, BOOTH 가격, DLsite 계정·결제 화면, Google 검색창, YouTube 입력창, X 표시 이름·핸들·작성창이 변하지 않는지 확인한다. 메신저 설정 또는 동의가 없을 때 DM도 추출·번역하지 않아야 한다.
6. 스크롤을 계속하는 동안 번역 결과가 레이아웃을 반복해서 밀지 않고, 멈춘 뒤 묶어서 적용되는지 확인한다.
7. 외부 번역기에서 페이지별 보호 한도에 도달하면 새 요청이 멈추고 팝업 사용량이 일치하는지 확인한다.
8. Chrome, Whale과 Firefox가 Windows 앱에 각각 연결 상태와 확장 버전을 보고하는지 확인한다.
9. Windows 앱에서 인터페이스 언어를 한국어, English와 RTL 언어로 바꾼 뒤 팝업을 다시 열어 문구·문서 방향과 숫자 형식이 같은 언어로 바뀌는지 확인한다.
10. 부모 탭을 명시적으로 켜거나 끈 뒤 같은 출처의 새 탭·팝업을 열어 상태가 이어지는지 확인한다. 자식 탭의 기존 선택, 다른 출처, 민감 경로·사이트 차단은 상속으로 덮어쓰지 않아야 한다.
11. 공개 카드 검색 라벨과 CSS로 펼친 메뉴가 번역되면서 입력값·체크 상태·숨긴 문구·가격·계정 영역은 바뀌지 않는지 확인한다.
12. 일반 페이지 복구와 초기 토글을 반복해 수신자·관찰자가 중복 생성되지 않고 마지막 선택이 유지되는지 확인한다.
13. 허용된 YouTube 임베드에서 보이는 제목만 번역되고, 부모 끄기·언어 변경·페이지 전송 한도·프레임 숨김이 반영되는지 확인한다. 채널명과 영상 자막은 바뀌지 않아야 한다.
14. 새 기능을 지원하는 본체에서 메신저 설정의 기본 꺼짐, 브라우저별 동의 취소·거부·허용·철회, Firefox 선택 권한 철회, 외부 모델 선택 시 차단을 확인한다. 공개 본체 `0.7.2-beta`는 이 기능의 검증 실행본으로 사용하지 않는다.
15. 허가된 테스트 대화에서 현재 보이는 본문만 번역되고 이름·연락처·목록·작성창·초안·첨부·전송 동작이 변하지 않는지 확인한다. 다른 대화로 전환하거나 탭을 닫거나 동의를 철회했을 때 이전 결과가 붙지 않고 일반 디스크 캐시·번역 기록·본문 로그에 사본이 남지 않아야 한다.

현재 웹 확장은 일반 HTTP/HTTPS 문서 사이트를 범용 지원한다. 실시간 YouTube 자막, PDF, 이미지 안의 글자, 브라우저 내부 페이지와 로그인·계정·결제 화면은 처리하지 않는다. 개인 메시지는 개발 중인 위 8개 서비스의 동의 기반 전용 경로 외에는 처리하지 않는다. 복잡한 웹 앱이나 독자적인 DOM 구조를 쓰는 사이트는 선택자가 일부 문단을 찾지 못할 수 있으며, 안전하게 식별하지 못한 영역은 원문으로 남긴다.
