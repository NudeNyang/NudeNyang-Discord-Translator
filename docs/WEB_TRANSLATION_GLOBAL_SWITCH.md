# 전체 웹 번역 ON/OFF

2026-08-28 · 미공개 개발 변경 · 확장 0.7.11

## 사용자 동작

F4, 기존 팝업 상단 토글, 보조 단축키는 모두 **현재 브라우저 프로필의 전체 웹 번역 상태**를 변경한다.
ON이면 기존 탭과 새 탭의 허용된 내용을 자동 번역하고, OFF이면 모든 탭의 새 전송을 차단하고
원문으로 복원한다. 주소창·브라우저 내부 화면에 포커스한 F4는 콘텐츠 스크립트가 받을 수 없지만,
팝업 토글과 브라우저가 배정한 보조 명령은 현재 페이지의 수집 지원 여부에 의존하지 않는다.

다른 브라우저·프로필과 앱 Discord의 켜짐 상태는 바꾸지 않는다. 본체의 웹 번역 사용 허용과
브라우저 연결은 기존 선행 조건이며, 사용자가 해제한 연결을 자동으로 다시 허용하지 않는다.
상태가 ON이어도 본체 연결·사이트 차단·메신저 동의 등으로 현재 페이지를 처리할 수 없으면
해당 페이지는 번역하지 않는다. OFF는 본체의 응답을 기다리지 않는다.

팝업의 중복 `이 사이트 자동 번역` 스위치는 제거했다. 페이지별 목표 언어, 사용량 표시,
앱 설정과 개인정보 안내 진입은 유지한다. 기존 `never` 사이트 차단은 보존하며 이전
`always`·`manual` 값과 어댑터의 수동 시작 기본값은 전체 ON을 막거나 OFF를 덮어쓰지 않는다.
본체 사이트 목록에서는 더 이상 `직접 시작`을 새로 선택하지 않는다.

## 근본 원인과 상태 구조

이전에는 앱 기능 허용, 탭 ID별 session 저장, 사이트 정책, 어댑터의 자동 시작 기본값이
중첩되어 있었다. 탭의 수동 ON은 독립적으로 연 다른 사이트의 새 탭에 전달되지 않았다.

- `extension/global-state.js`: 브라우저 local 저장소의 `webTranslationEnabled`와
  `webTranslationConsentVersion`을 관리한다. 여러 탭의 toggle/set을 한 큐로 직렬화한다.
  과거 `enabled`, 탭별 session 값, 메신저 동의를 새 전체 ON으로 승격하지 않는다.
- `extension/background.js`: 토글 발신자를 검증하고 모든 탭에 재조회 알림을 보낸다.
  번역 요청은 메신저 검증 전과 Native Messaging 송신 직전에 전체 상태·세대를 확인한다.
  OFF 후 ON해도 이전 세대의 대기 요청·응답은 되살리지 않는다.
- `extension/content.js`: 전체 상태와 기존 페이지 안전 조건을 함께 검사한다. OFF 시
  원문을 복원하고, 다시 ON이면 아직 유효한 완료 번역을 재사용한다. 늦은 상태 조회가
  최신 OFF나 철회를 덮어쓰지 않도록 한다.
- `extension/popup.js`: 페이지 상태와 별도로 전체 상태를 표시한다. 번역 불가 페이지나
  연결 끊김 때문에 이미 켜진 전체 상태를 끄지 못하는 문제를 방지한다.

저장 실패는 성공으로 표시하지 않는다. OFF 저장 실패 시에는 적어도 현재 백그라운드 세션의
전송을 차단한다. 저장소 장애 중의 다음 브라우저 재시작까지 영속성을 보장하지는 않는다.

## 고지·동의와 개인정보

동의 v1은 **전체 자동 번역 범위의 동의**이며 기존 메신저 정책 v3과 별개다.
설치·업데이트 뒤 아직 동의하지 않았다면 기존 개인정보 화면을 `?scope=web` 모드로 연다.
첫 F4/ON도 동의가 없으면 같은 안내를 열 뿐 본문을 전송하지 않는다.
확인란과 기존 동의 버튼을 직접 사용해야 전체 ON이 저장된다.

안내는 기존·새 탭, 보이는 웹페이지 내용, 이미 허용한 메신저 대화, Windows 앱의
로컬/외부 번역기, 암호화 캐시·보관·삭제·시크릿 처리 범위를 설명한다. 28개 UI 언어를 제공한다.
일상 조작용 버튼을 추가하지 않고 기존 동의 화면을 재사용한다.

전체 동의가 메신저 동의나 Firefox `personalCommunications` 선택 권한을 대신하지 않는다.
메신저 안내는 기존 경로로 접근할 수 있고 이를 거절해도 일반 웹 번역은 사용 가능하다.
전체 동의 철회는 전체 번역을 끈다. 캐시 삭제와 동의 철회는 별개이며 기존 본체 삭제 설정을 따른다.
닉네임·핸들·URL·이메일·코드·입력값·대화 경계·시크릿 저장 금지와 자연어 링크 문구 번역은 유지한다.
일반 ON/OFF만으로 숨은 탭의 개인 대화를 새로 읽도록 만들지 않는다.

Chrome의 [고지·동의](https://developer.chrome.com/docs/webstore/program-policies/disclosure-requirements)와
[목적 제한](https://developer.chrome.com/docs/webstore/program-policies/limited-use),
Firefox의 [데이터 전송 정책](https://extensionworkshop.com/documentation/publish/add-on-policies/#data-collection-and-transmission-disclosure-and-control)을 기준으로 설계했다.
Firefox의 Native Messaging도 동의 정책 대상이다. 실제 제출 전에는 스토어 설명과 개인정보
처리방침·대시보드의 데이터 고지가 이 동작과 일치하는지 확인해야 하며, 심사 통과를 보장하지 않는다.

## 검증

수정 전 실패한 재현은 도메인 독립 공개 HTML 두 개를 사용한다. 첫 탭에서 F4로 켠 다음
opener 없는 다른 사이트 새 탭을 열면 원문으로 남았다. 수정 후 새 탭 번역, 새 탭에서 OFF,
첫 탭 원문 복원과 새로고침 뒤 OFF 유지가 통과했다.

추가 회귀는 팝업 문서와 F4의 상태 공유, 지연된 번역의 OFF 처리, 메신저 대기 중 빠른 OFF·ON,
새 동의 전 미전송, 명시적 동의 후 시작·철회, 동시 토글·저장소 실패·백그라운드 상태 재생성이다.
전체 E2E 및 공개 표본 검사는 별도로 실행한다. 합성 페이지와 모사 Native Messaging을
사용한 검증은 실제 로그인 사이트·실제 AI 추론·Whale/Firefox 키 입력 검증과 구분한다.
본체 번역 엔진이나 모델은 이 작업에서 변경하지 않는다.

첫 빌드는 브라우저가 재생성한 Native Messaging 프로세스의 실행 파일 잠금으로 실패했다.
해당 경로의 프로세스만 종료하고 이전 실행 파일을 보존한 뒤 재빌드하여 통과했다.

팝업 E2E는 실제 `popup.html`을 확장 탭으로 열어 검사하며 브라우저 도구 모음의 팝업 창 자체를
자동 조작한 검사는 아니다. 밝은/어두운 테마의 커스텀 툴팁 화면과 경계도 확인했다.
F4는 실제 페이지 키 입력을 사용하고 보조 단축키는 확장 명령 이벤트를 호출하므로 OS의 키 배정
충돌 검증을 대신하지 않는다. 개인용 Chromium, 스토어용 Chromium ZIP, Firefox XPI를 로컬 생성하고
전체 상태 모듈 포함·구형 탭 모듈 및 테스트 코드 제외를 확인했다. 확장 0.7.11 버전과 개인용 ID는 유지한다.

릴리스·스토어 제출·푸시는 수행하지 않는다. 개인용 확장을 다시 로드하고 기존 탭도 새로고침해야
새 콘텐츠 스크립트가 적용된다. 첫 ON 때 전체 범위 안내에 동의한 뒤부터 상태를 계속 기억한다.
