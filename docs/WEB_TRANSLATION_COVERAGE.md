# 웹 번역 누락 진단과 구조 검증

최신 [읽기 범위 확대](WEB_READING_SCOPE.md)에서는 UI 구조 96개를 추가 검사한다.
폼 전체를 가지치기하는 대신 읽기용 라벨·연결된 설명을 검사하되 입력값은 읽지 않는다.
메일과 정적 UI 전용 계정 화면에서는 독립 전체 본문 진단을 실행하지 않는다.
아래 검증 수치는 해당 문서를 처음 작성한 단계의 기록이다.

기준: 2026-08-29 프리릴리스 소스. 확장 0.7.11, 본체 0.7.4-beta.
공유용 0.7.10 파일은 변경하지 않는다. 푸시·공개 릴리스·스토어 제출은 수행하지 않는다.

## 작업 순서

누락 사유 추적 → 독립 누락 검사 → 구조 자동 생성 테스트 → 공개 페이지 표본 검사 →
최소 HTML 재현의 실패 확인 → 공통 원인 수정 → 전체 회귀 검사 순으로 진행한다.
모든 사이트의 완전 번역을 증명하는 방법이 아니라, 사용자가 신고하기 전에 새로운 구조의
누락을 발견하기 위한 체계다.

## 구현과 진단

| 파일 | 역할 |
| --- | --- |
| `extension/dom-policy.js` | `explain`의 허용/제외 이유와 원문 읽기 전 `auditBoundary` |
| `extension/content.js` | 기존 노드 기록의 처리 단계, 자동 진단 예약, 상태 조회 |
| `extension/translation-audit.js` | 수집기의 블록 선택자를 사용하지 않는 독립 순회 |
| `extension/test/fixtures/generated-structures.mjs` | 정답을 미리 정한 2,048개 구조와 실패 축소 |
| `extension/e2e/coverage.spec.mjs` | 실제 Chromium의 구조 변형·진단·공통 원인 회귀 |
| `extension/e2e/public-samples.spec.mjs` | 명시적으로 실행하는 공개 표본 검사 |

독립 순회는 `collectBlocks`를 호출하지 않는다. 안전 경계는 공통 정책과 공유하되,
별도로 발견한 Text 노드가 수집·전송·적용 기록에 있는지 확인한다. 수집기만 일부러 고장 낸
E2E에서도 누락을 찾는다. 같은 선택자를 검사기에 복사하여 같은 누락을 숨기지 않는다.

| 상태 | 의미 |
| --- | --- |
| `undiscovered` | 허용된 보이는 텍스트의 블록이 수집기에 등록되지 않았다. |
| `not_queued` | 블록은 등록됐지만 해당 텍스트의 요청 기록이 없다. |
| `queued`, `requesting`, `response_received` | 전송 대기, 응답 대기, 표시/나머지 조각 대기 |
| `missing_result`, `request_failed` | 결과 항목이 없거나 비어 있음, 요청 실패 |
| `quality_failed` | 본체가 `cacheable:false`로 표시한 불완전 결과 |
| `unchanged_result` | 원문과 같은 결과. 목표 언어·고유명사일 수 있으므로 실패로 단정하지 않는다. |
| `apply_lost`, `source_changed` | 준비된 결과가 표시되지 않음, 사이트가 다른 내용으로 변경함 |
| `applied`, `replayed` | 현재 표시된 결과, 재생성된 노드에 캐시 결과 표시 |
| `offscreen`, `usage_limited`, `cancelled` | 화면 밖, 기존 전송 한도, 취소 |

`excluded`는 보호·비가시성·폼·정책 제외의 이유별 집계다. `review`에는 `excluded_scope`와
`outside_scope`의 구조 표본을 별도로 남긴다. 제외 판단이 올바르다는 증거는 아니므로
누락 의심이 있으면 검토한다. 제외한 노드의 내용은 읽지 않아 공백 Text 노드도 집계에
포함될 수 있다. 진단기가 임의로 번역을 허용하지 않는다.

`unsupported`는 iframe, 그림 영역, 접근 가능한 Shadow root의 별도 집계다. 기존 제한된
임베드 제목 기능과 구분하며 전체 프레임이 번역됐다고 계산하지 않는다. 닫힌 Shadow root나
이미지 속 글의 존재까지 이 검사로 알아낼 수는 없다.

### 실행 범위·개인정보·성능

- 번역이 켜진 공개 탭만 자동 검사한다. 메신저·민감 경로·비활성/숨겨진 탭에서는 독립
  전체 문서 검사를 하지 않는다. 기존 메신저 범위·동의·번역 정책은 변경하지 않는다.
- 보호·편집·작성자·폼 영역은 원문을 읽기 전에 가지치기한다. 검사 때문에 원문, URL,
  클래스, ID, 텍스트 해시를 로그/서버/저장소로 보내지 않는다.
- 결과는 탭 메모리에만 보관한다. 집계와 최대 40개 의심 표본·40개 제외 검토 표본에
  순회 순번·태그 종류·사유만 포함한다. 순번은 DOM이 바뀌면 달라지며 사용자 식별자가 아니다.
- 스캔·표시·스크롤 후 요청을 합쳐 검사한다. 자동 검사는 직전 종료 후 최소 5초 간격,
  최대 5,000개 노드·1.5초이며, 100개 노드 또는 약 8ms마다 브라우저에 실행을 양보한다.
  가시성 계산은 검사 안에서 재사용한다. 최초 예약은 페이지 시작 후 경과 시간에 따라 다르다.
- 작업량 제한은 `limited`, 페이지/DOM 상태 변경·OFF는 `cancelled`, 실행 불가는
  `unavailable`이다. `complete`는 순회를 마쳤다는 뜻이지 번역 성공률 100%가 아니다.
- 진단은 DOM을 수정하거나 번역을 재요청하지 않는다. 기존 캐시 복원과 본체 품질 재시도를
  유지하며, 진단 때문에 보호 규칙을 우회하거나 실패 문장을 무한 재번역하지 않는다.
- 확장 내부의 `nudenyang-audit` 메시지로 명시적 검사를 실행한다. 발신 확장 ID를 검사하고
  웹페이지에는 메시지 브리지를 노출하지 않는다. 일반 상태의 `coverage`는 최신 진단이다.
  새 사용자 토글이나 기본 툴팁은 추가하지 않는다.

## 자동 생성 검증

2,048개는 문단 태그 4종 × 중립 래퍼 깊이 4종 × 인라인 요소 4종 × CSS 배치 4종 ×
줄바꿈 분할 2종 × 문맥 컨테이너 4종의 전체 조합이다. 기대 원문은 생성기가 먼저 정한다.
제품의 허용 판단으로 기대값을 만들지 않는다. 중복 수집과 보호 본문 유출도 검사한다.

실패하면 실패 조건을 유지하는 래퍼·배치·태그 축소를 시도하고 최소 후보 HTML을 출력한다.
이는 생성기 차원 안에서의 축소이며 범용 HTML 최소화 도구는 아니다. 모든 HTML을
생성하는 것도 아니다. 새 구조를 발견하면 생성 차원을 추가한다.

Chromium에는 결정적인 32개 조합을 뽑아 늦은 삽입, 노드 재생성, 요청 없는 캐시 복원,
원문 변경, OFF 복원을 검사한다. 별도 CSS·보호·응답 경합 회귀도 전체 E2E에 유지한다.

## 공개 페이지 검사

```powershell
npm test
npm run test:e2e
npm run test:public
```

`test:public`은 기본 E2E와 별도로 실행한다. 임시 Chromium 프로필에 실제 개발 확장을
로드하며 사용자 Chrome 프로필·로그인·쿠키·본체 Native Messaging에는 연결하지 않는다.
현재 표본은 뉴스 홈, 뉴스 기사, 기술 문서, 공개 게시판, 언어 포털, 공개 데모 카탈로그다.
목록의 도메인은 테스트 입력이지 제품의 예외 규칙이 아니다.

각 페이지의 0/33/66/100% 지점으로 스크롤하고 대기 상태가 가라앉은 뒤 집계한다.
주 문서와 명시한 정적 자원 호스트에 GET만 허용한다. 다른 페이지 이동·로그인·구매·댓글 작성,
임의 API·POST·외부 번역 전송은 하지 않는다. 따라서 일부 동적 API/제3자 위젯은 로드되지
않을 수 있으며 실제 로그인 사이트를 대신하지 않는다. 접속 실패·읽을 텍스트 없음·제한된 검사·
미해결 의심 항목은 성공으로 처리하지 않는다. 표본의 접근 조건이 바뀌면 별도 조사한다.

번역 엔진은 `번역(원문)`을 반환하는 모사 엔진이다. DOM 경로의 누락 탐지이며 번역 품질
평가는 아니다. `review`의 제외가 모두 적절하다고 보증하지도 않는다.

본문 없이 집계만 `test-results/extension-public/*/coverage.json`에 보관한다.
공개 표본의 native 요청 본문·화면·trace는 저장하지 않고 Playwright의 자동 페이지
스냅샷도 끄도록 고정 버전 실행기를 설정했다. 실패 사유/테스트 소스는 남을 수 있다.
합성 E2E는 기존대로 실패 trace·화면·요청 기록을 남긴다. 두 결과 폴더는 서로 덮어쓰지 않는다.

## 확인한 공통 원인과 수정 전 실패

1. **본문 구역의 제목을 전역 머리말로 취급:** 공개 기사에서 `section → header → h2`를
   확인했다. 구역의 의미가 분명한 제목만 허용하고 작성자·폼·임의 전역 header는 보호한다.
2. **`display:contents`의 크기 0을 비가시성으로 취급:** 보이는 자식 텍스트의 범위를
   확인한다. 크기가 없는 블록은 알려진 제한된 목록을 스크롤 후 합쳐 검사한다.
3. **float 자식이 있는 inline 부모의 너비 0:** 데모 카탈로그 하단의 페이지 이동 링크를
   자동 검사가 `not_queued`로 발견했다. 도메인 없는 `li → float a`로 먼저 실패시킨 뒤
   같은 텍스트 범위 판단을 적용했다. 사이트 선택자는 추가하지 않았다.

세 재현 모두 실제 Chromium에서 수정 전 실패, 수정 후 통과를 확인했다. 진단 기능도
추가 전 테스트 실패를 확인했다. 공개 표본 검사는 처음 5개 통과/1개 실패였고 float 공통
수정 뒤 6개 모두 통과했다. 사이트 예외 대신 최소 재현을 고정하는 흐름을 실제로 수행했다.

야후 화면의 모든 일본어가 같은 원인이라고 판정한 것은 아니다. 공개 댓글의 DOM 구조와
당시 실제 모델 결과는 별개이므로 이번 결과로 그 화면의 모든 문장이 완전히 번역된다고
주장하지 않는다. 실제 Hy-MT2 검증은 기존 공개 문단 3개의 별도 통합 테스트로 실행한다.

들어 있고 테스트 파일은 들어 있지 않은지도 확인했다.
